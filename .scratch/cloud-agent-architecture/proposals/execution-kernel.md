# 执行内核与适配边界提案

状态：superseded。用户后续明确选择复用成熟执行器的 Agent loop，本稿保留为历史取舍，由[执行器复用方案](execution-harness.md)和 [ADR-0002](../../../docs/adr/0002-reuse-agent-harnesses.md) 取代。Python 语言选择保留；下文的自建内层循环和 LangGraph 必选组合不再是当前实现要求。

## 已确认决定

首版采用原生 Agent 工具循环，并由 LangGraph 承载可恢复的执行编排和业务阶段暂停。平台使用供应商客户端 SDK 调用模型，自行实现目标上下文装配、模型动作处理、工具请求与结果回传、终止判断和标准事件。

不将现成完整 Agent SDK 或桌面 CLI 定为首版核心执行依赖。需要复用的是模型通信、图编排与协议实现，避免重新实现供应商 HTTP 协议或通用图引擎。

首版采用 Python 执行内核与 LangGraph 编排，配套应用框架沿用 FastAPI、React 与 TypeScript 的方案。具体版本在实施规格锁定，数据库结构、队列方案和沙箱路线由后续决策确定。PostgreSQL 作为持久化候选保留，不在本票宣称已经决定全部存储设计。

## 三条路线与取舍

| 路线 | 收益 | 本项目承担的工作 | 结论建议 |
| --- | --- | --- | --- |
| 原生工具循环 + LangGraph | 模型调用、工具入口、上下文和双模式阶段控制可直接组织和观察 | 工具循环、事件、取消传播、上下文政策、平台状态与权限 | 推荐，接受明确的内核工程工作换取控制与可验证性 |
| 现成 Agent SDK | 可复用成熟循环、工具和部分会话能力 | 仍需阶段审批、成员持久身份、云端权限及业务恢复；须验证供应商范围和运行依赖 | 不作为首版唯一核心；未来出现实际接入需求时再评估 |
| 既有执行引擎/CLI 适配 | 可利用已有执行器行为和工具能力 | 宿主改造、协议归一、进程治理、上游升级和业务语义适配 | 不作为首版依赖；已有源码用于方法参考 |

SDK 自带 Agent 循环与模型客户端 SDK 是两种用途。推荐方案仍正常使用供应商客户端 SDK，选择的是平台自行拥有 Agent 执行循环。

## 最小模块职责

| Module | 调用者得到的能力 | 隐藏的 Implementation |
| --- | --- | --- |
| 任务编排 | 提交目标、响应确认、查询执行状态 | 模式路由、阶段推进、用户消息排队、检查点协调、确认版本与最终完成判断 |
| AgentRuntime | 对一个会话发起或继续一轮执行，获得标准事件并发起停止 | 上下文装配、模型动作处理、工具循环、用量累计、停止传播与执行快照 |
| 工具执行 | 使用类型化参数调用一个已获准能力，得到明确结果 | 参数校验、权限判定、扩展/MCP 调用、隔离环境操作、超时与结果记录 |
| 协作管理 | 创建成员、指派、汇报和停止成员 | 持久身份、独立会话、消息回执、成员权限及总预算协调 |

模块可以在同一应用进程内组成模块化单体，不因分出职责就拆成多个微服务。长任务运行于独立执行进程，不依赖浏览器连接持续在线；具体 Worker 与租约由后续票决定。

长期指令、项目记忆、Skill 和成员信息由平台保存并按权限提供给 Runtime；模型不会拥有这些对象的最终管理权。协作成员各自使用 Runtime，会话持续存在不代表底层进程必须永久在线。

## 双模式共用方式

自由模式：用户目标进入动态执行流程，Agent 选择工具与方法，按照约定检查结果；用户自行设置的确认点照常生效。

需求开发模式：任务编排依照阶段、输入输出与确认状态，决定何时调用同一个 Runtime 及应加载哪个阶段 Skill。预置 Skill 负责方法指引，程序检查阶段成果和确认是否满足退出条件。

两种模式共用工具执行、权限、记忆、协作与事件语义。流程模板属于任务编排，不能由模型一句“进入下一步”直接替代。LangGraph 可表达业务阶段与执行步骤，不把每段流式 token 设计成业务节点。

## AgentRuntime 的 Interface

公开 Interface 只覆盖以下行为，详细类型在实施规格确定：

1. 发起或继续本轮：传入稳定会话/执行标识、目标、允许使用的上下文引用、配置版本、能力范围和预算，返回执行标识及接收结果。
2. 立即补充：明确针对当前轮次；返回已接受、不支持、已结束或待安全点等实际结果。普通消息排队由任务编排管理，不能由 Runtime 隐含吞入下一轮。
3. 停止：返回停止请求回执，后续事件明确停止确认或结果不明，不能把请求已收到等同于所有工具已经终止。
4. 读取执行事件：模型公开文本、工具请求/结果、用量、待交互、候选结果、停止与错误均具有执行关联；不输出模型私有推理或明文凭据。

不变量：同一会话同一时刻只有一个前台执行轮次；旧轮次迟到结果不能覆盖新轮次状态；Runtime 只产出候选成果，任务编排和验收决定产品是否完成。

失败规则：模型结构错误、工具执行失败、停止未确认和结果不明分别表达。检查点恢复不能代替副作用去重或核对。立即补充只能在真实支持的动作边界实施，不宣称能够修改已经送出的模型请求或撤销已经发生的工具效果。

## Adapter 与自建范围

- 供应商客户端放在模型调用的 Seam，负责请求/工具 schema、流式事件、取消能力和用量的归一。只实现实际接入的供应商，测试通过固定响应实现替换；不提前建设支持所有引擎的全能 Adapter。
- 模型可以切换不代表任意供应商完整兼容；每个正式接入都要验证工具历史、结构化输出、上下文和取消行为。
- 平台实现工具执行和权限政策；文件、终端、MCP 等具体能力使用标准库、官方客户端或成熟依赖，避免自行创造协议。
- 平台实现持久协作的产品语义，临时子 Agent 与持久协作者共用 Runtime 能力，分别维护生命周期。
- 使用 LangGraph 的检查点和中断机制，不另造通用状态图框架；框架保存状态不等于自动获得业务确认版本或工具幂等。

## 通过同一 Interface 验证

- 固定模型响应和受控工具可验证决策、工具回传、错误与停止的外部行为，不访问 Runtime 私有结构。
- 真实模型与真实工具另做集成评测，验证供应商兼容和成果质量，不用一次随机输出决定一般 CI。
- 必须推演：人工确认挂起后恢复；工具已生效但结果未保存时中断；停止后迟到输出；立即补充投向已经结束的轮次；成员重复派发。
- 本票没有运行测试或性能结果；实际持久恢复、工具去重和租户隔离在后续设计及验证中证明。

## 确认范围

采用 Python 原生循环 + LangGraph 的路线及以上职责分配，平台自行实现执行循环、上下文和统一工具入口；不把完整 Agent SDK/CLI 作为首版核心依赖。Java 的可行性研究保留为备选依据，选择 Python 不意味着 Java 无法满足产品功能。
