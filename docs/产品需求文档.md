# 云序 Agent 工作台 · 产品需求文档

版本：v0.7 统一任务入口  
更新日期：2026-11-06  
文档性质：产品需求基线与范围整理，包含待交付目标，不表示全部功能已实现。

本文整合此前确认的产品决定及后续使用反馈。原始详细草案与 AC-01～AC-49 编号保留于 [PRD v0.4](PRD.md)，实际实现及验证证据见[实现状态](implementation-status.md)。技术架构与接口协议由技术方案及 ADR 说明。

## 1. 产品定义

云序是面向开发者和技术型个人用户的 Agent 工作台。用户以项目组织材料，向 Agent 委托目标，查看执行过程，在关键决策处参与确认，最终获得可查看、下载、继续修改的成果。

平台统一提供一个任务入口。研究、数据处理、脚本和软件开发由目标与材料表达，不要求用户选择自由或需求开发模式。Agent 根据目标动态规划、按需选择 Skill、执行并验证；用户可以指定“只做研究”“先出方案等确认”或“直接实现并测试”。Auto／Ask 独立控制工具授权，交付前人工验收可按任务选择。

实际模型决策与工具循环优先复用成熟执行器。平台负责项目、任务、阶段、权限、记忆、协作、运行记录及交付验收。执行器选择与模型选择分别表达。

### 1.1 用户问题与产品收益

| 用户问题 | 产品提供的能力 | 可观察收益 |
| --- | --- | --- |
| 多次对话后材料、目标和成果难以关联 | 长期项目、独立任务、共享资料与历史记录 | 后续修改可从现有成果继续 |
| 执行过程不透明，无法判断是否需要介入 | 任务状态、工具活动、待处理卡片和阶段导航 | 用户知道进展、阻塞及下一步 |
| Agent 过早实现或需求变化后沿用旧方案 | 阶段流程、需求版本与人工确认 | 实作依据清楚，变更可追溯 |
| 逐工具授权打断执行 | Auto／Ask 工具授权策略 | 常规操作可连续推进，风险有审核记录 |
| Agent 声称完成但成果或验证缺失 | 交付清单、检查证据、有限修复与成果快照 | 完成结论有对应依据 |
| 断线或进程异常后不知道是否已执行 | 持久状态、队列和结果不明处理 | 保留资料，核对后决定如何继续 |

### 1.2 成功标准

1. 发布版本允许用户通过网页创建项目并启动任务，无需准备个人执行环境。
2. 用户能区分执行中、等待自己、已停止、部分完成和已交付。
3. 每次交付关联实际成果、适用检查、未完成项与具体版本。
4. 已保存的材料、确认和成果在页面重连后仍可访问。
5. 同一项目可持续开展多个任务，并保留历史交付。

当前开发版仍需运维配置执行器环境；云端可用性和多租户隔离不因网页可访问而视为已完成。

## 2. 目标用户与场景

首批用户为独立开发者、技术学习者及有研究、数据或代码任务的技术型个人。主要使用桌面浏览器，首版采用个人账户与个人项目。

| 场景 | 典型输入 | 预期成果 | 验收依据 |
| --- | --- | --- | --- |
| 技术研究 | 研究目标、比较维度、公开资料 | 研究报告、来源、比较结果 | 关键事实可追溯，未知项明确 |
| 数据处理 | CSV、清洗规则、分析目标 | 数据、脚本、图表与口径说明 | 结果可复查，异常处理明确 |
| 代码修改 | 公开仓库或已有文件、修改目标 | 代码变更、运行说明、测试记录 | 必要功能检查通过 |
| 应用原型 | 功能描述、交互要求、参考材料 | 应用代码、受控预览、交付说明 | 可启动，关键交互有证据 |
| 持续迭代 | 原成果与新增要求 | 新版本成果、变更摘要 | 新条件重新检查，旧版本保留 |

## 3. 范围与版本

### 3.1 首个完整产品版本的范围

账户与个人项目、资料导入、多任务对话、统一任务与动态计划、执行器接入、工具授权、扩展与 MCP、长期指令与项目记忆、持久及临时 Agent 协作、成果与预览、检查与修复、队列与异常恢复、预算与数据生命周期管理。

### 3.2 首版不包含

- 跨用户团队协作、多人实时编辑、公开项目分享。
- 私有仓库账户连接、第三方网站登录代操作。
- 自动向外部发送消息、推送代码、发布、部署或支付。
- 用户电脑执行客户端、远程桌面、SSH 和交互式云终端。
- 长期网站托管、交易型插件市场、模型训练。

公开网页访问不代表访问受限资料；安装扩展不能扩大产品业务范围。

### 3.3 当前开发版与目标的关系

| 能力 | 当前开发版边界 | 完整版本仍需补齐 |
| --- | --- | --- |
| 执行环境 | 已按用户授权启用可信本机执行；默认配置仍禁用执行 | 云端环境交付、强隔离、认证运维与资源管理 |
| 执行器 | 两种适配已实现；Codex 已有真实回复、文件操作记录 | Claude 带凭据验证及双引擎完整异常场景 |
| 开发流程 | 新任务统一入口，按目标执行；旧阶段保留兼容与显式转换 | 原生计划与按需方法的可观察性、明确约定的中途确认 |
| 扩展 | 项目 Skill／无明文密钥的 stdio MCP 配置与快照 | 扩展发现、包安装、审核、原子更新、凭据生命周期 |
| 记忆 | 分类管理、检索、可选结构化事实导入 | 整理质量、修订审计与系统化效果验证 |
| 协作 | 持久成员、独立工作区与会话、基线冲突检查 | 自动指派、成员并行、全组停止与临时子 Agent 汇总 |
| 预览 | 隔离静态 HTML／文本预览 | 应用进程管理、端口代理、休眠与唤醒 |
| 数据管理 | 成果快照、按文件恢复、项目回收与恢复 | 永久删除、保留期、账户硬配额 |

以上为已记录的实现边界，不是本次对所有功能重新进行的运行验收。

## 4. 核心对象

| 对象 | 定义与关系 |
| --- | --- |
| 项目 | 长期组织相关工作，拥有资料、工作空间、任务与设置 |
| 任务 | 围绕一个目标的独立对话与工作单元，可包含多次执行 |
| 执行轮次 | 一次派发的工作过程，拥有独立状态、事件与检查记录 |
| 原生会话 | 执行器保存的上下文，与平台任务、执行轮次分别标识 |
| 阶段 | 有输入、预置方法、产出与退出条件的流程节点 |
| 人工确认 | 用户对具体需求、阶段成果和版本的决定 |
| 工具授权 | 对具体操作或执行策略的权限决定，与人工验收独立 |
| 成果及检查 | 文件、变更或预览入口，以及判断要求是否满足的证据 |
| Skill／MCP／插件 | 分别承担方法资源、工具连接、可安装能力包的职责 |
| 长期指令／记忆 | 用户主动设置的持续要求，以及可复用的项目事实 |
| 持久协作者 | 有独立职责、会话、指派及历史的 Agent 成员 |

同项目任务共享文件，不自动复制彼此的完整对话。跨执行器继续工作时建立新原生会话，明确传递的材料范围。

## 5. 用户主流程

1. 注册登录，创建或打开项目，上传材料或导入公开仓库。
2. 创建任务，选择执行器、模型及工具授权策略，描述目标与约束。
3. Agent 澄清关键缺失条件；非关键缺失说明默认假设。
4. 展示目标理解、主要步骤、预期成果及检查条件，按目标和约定开始执行。
5. 用户查看活动、文件和预览，可补充、纠正、停止或处理确认卡。
6. Agent 生成成果并进行适用检查，必要时在预算内修复。
7. 平台展示交付状态、文件、证据和限制，用户下载或继续修改。

关键问题未解决时不假定用户同意；同版本已有的明确授权应保留来源，避免重复确认。

## 6. 统一任务与动态执行

用户创建任务时填写目标与材料，可选择执行器、模型、Auto／Ask 和交付前人工验收，不再选择任务模式。Agent 根据任务需要理解目标、规划、实现、验证与修复，步骤可调整、复用或省略，不设强制七阶段及三个默认人工门。

Skill 由用户指定或 Agent 按需选择。软件开发可提供推荐模板与方法组合，不另设模式。关键条件缺失时集中提问，用户明确要求先确认时等待；同一有效授权不重复询问。工具授权、问题答复及业务验收分别记录。

需求变化使受影响的交付确认失效，保留已有资料、执行和成果。用户随时补充、排队、停止或继续；原生能力不支持即时纠正时如实说明。

旧版阶段记录仅作历史兼容，禁止新建固定阶段开发任务。旧任务提供显式转换为统一任务的操作，需先停止执行，保留旧阶段、确认和成果记录，不伪造已通过历史。

## 7. 功能需求

### F-01 项目、材料与生命周期

支持创建项目、文件上传、ZIP 和公开 Git 仓库导入，显示来源、版本、成功项及失败原因。完整版本支持导入分支或提交选择、同名文件冲突处理。当前仓库导入仅限公开 GitHub HTTPS。

文件支持查看、适用文本编辑、下载和版本检查。导入路径不得越界，链接与保留目录不能绕过检查。无法解析材料时说明限制，不按文件名编造内容。

项目资料持续保留；归档、回收、恢复、永久删除具有不同后果。历史文件恢复前确认覆盖范围，执行中拒绝恢复；恢复文件不宣称撤销网络等外部副作用。

### F-02 对话、队列与任务控制

消息显示收到、排队、派发等状态。同项目共享主工作区的任务串行，跨项目可在账户预算内并行。普通补充进入可见队列，派发前可编辑或撤回。

立即纠正以执行器真实能力和接收回执为准；不可用时说明，允许用户选择排队或停止后执行。停止需等待原生终态，保留文件和历史，并暂停未派发消息，不能自动重启。

网页重连补齐事件、当前状态及待处理卡片，不重复创建执行。运行异常、结果不明时先核对再决定是否重试。

### F-03 执行器与模型

首批接入 Codex 与 Claude Code。分别展示可用能力、环境、模型和认证状态。依赖或镜像存在不等于认证可用；缺少认证时明确提示。

原生标识按执行器保存，不跨引擎复用。新会话交接保留用户目标及必要材料，说明未覆盖的历史和能力差异。执行器结束与平台任务交付分别判定。

### F-04 Auto／Ask 工具授权

默认 Auto，用户可按任务切换 Ask；首版不提供 Full Access 选项。

- Auto：常规授权范围内工作连续推进；需要审核的操作交由原生风险审核或平台要求的人工确认。
- Ask：需要权限决定时交由用户处理；不要求把每次模型思考也变成确认。
- 审核拒绝、超时、取消和回退应有记录，不自动转换为批准。
- 参数、范围或配置变化后，不复用不适用的旧授权；恢复会话不得继承过期策略。
- 原生工具与 MCP 均须遵守实际约束。自动审核不能作为扩大业务范围或多租户隔离的证明。

Codex 当前复用原生风险审核；Claude 的原生 Auto 尚待带凭据验收。具体协议映射见 [ADR 0004](adr/0004-native-auto-permissions.md)。

### F-05 Skill、插件与 MCP 扩展

区分方法、连接和能力包，展示来源、类型、版本、所需权限、配置及就绪情况。完整版本支持发现、安装、更新、卸载、兼容性检查和项目覆盖规则。

明确区分“已安装”“项目启用”“本次实际加载”。运行记录保留配置快照。更新损坏时保留旧版本；新增权限需重新审核，禁止静默提权。

停用或撤销应影响后续调用，并说明在途动作能否停止。凭据采用独立生命周期管理，不写入普通文件、记忆和日志。当前开发版只接收受限的无明文密钥 stdio MCP 配置。

### F-06 个性化与项目记忆

支持账户长期指令与项目约定，保存时说明生效范围。自主项目记忆默认关闭，用户启用后可自动保存有长期价值的事实，无需逐条确认。

记忆按 user、feedback、project、reference 分类，具备来源、修订及项目范围。支持查看、搜索、编辑、删除；不因分类相同而跨项目传播，不将所有历史对话自动纳入长期记忆。

关闭或删除记忆后停止后续自动注入，说明当前原生上下文仍可能包含之前加载的信息。整理失败保留原记录，建议与实际变更分别展示。

### F-07 Agent 协作

持久协作者保留独立身份、职责、原生会话、历史及工作区，可再次指派；临时子 Agent 作为本轮执行细节展示。

完整目标支持成员模型与权限设置、可追踪指派、汇报、预算汇总和全组停止。成员不隐式继承更高权限。创建成员不等于已经派发任务，失败指派不得显示为正在执行。

成员在独立修改区形成结果，应用前核对基线与冲突；结果完成顺序不能决定覆盖顺序。主 Agent 对整体结果负责，不能用单个成员完成代替任务验收。

### F-08 成果、检查与修复

交付关联具体需求版本、运行和真实成果，提供摘要、文件、运行步骤、检查及限制。展示以下不同结果：通过、失败、未验证。

平台核验与执行器报告分别标记。文件存在不能替代功能正确性验证；未执行的测试不能标为通过。必要检查不通过时不交付为完整成功，非必要限制需明确说明。

检查失败进入有限修复，预算耗尽后保留部分成果和失败原因。历史快照可下载与按文件恢复。

页面只将当前版本本轮失败作为当前错误；过去失败默认归入可展开历史，成功补修后旧错误不继续冒充当前状态。检查记录按运行关联，避免混入旧轮次结果。

### F-09 预览

静态预览与运行应用预览分别表达。预览须验证用户与项目权限，采用合适的浏览器隔离，不借预览访问平台身份或其他项目。

完整运行预览应展示进程启动、运行、失败、停止和休眠状态，支持重新启动，采用受控端口访问。预览退出不等于成果文件丢失，也不等于整个任务失败。

当前版本仅提供受限静态预览，未实现通用应用进程与端口代理。

## 8. 状态与异常规则

任务、执行轮次、流程阶段、待执行消息、预览和项目生命周期分别记录。

| 用户可见状态 | 语义及处理 |
| --- | --- |
| 待开始／排队 | 要求已保存，尚未执行；可修改或撤回 |
| 执行中 | Agent 正在规划、操作或检查；可补充或停止 |
| 等待信息 | 必要条件未齐，等待用户补充 |
| 等待授权 | 具体动作尚未获准，等待批准或拒绝 |
| 等待阶段确认 | 已提交当前阶段成果，尚未通过人工门 |
| 正在停止 | 已记录停止意图，仍在等待终态 |
| 已停止／暂停 | 执行结束或队列暂停，已有成果保留 |
| 恢复中／待核对 | 正在恢复已保存状态，或执行副作用不确定 |
| 已交付 | 适用必要条件满足，人工验收要求已完成 |
| 部分完成／无法完成 | 有明确缺口，展示已有成果、证据及后续选项 |

执行中崩溃后不得自动重放危险动作。恢复原生上下文、恢复文件及恢复进程是不同能力，界面须如实说明。预览失败、可选检查未执行、强制验收未通过分别表达。

## 9. 页面信息结构

| 区域 | 核心内容 |
| --- | --- |
| 项目入口 | 创建、导入、搜索、最近活动、回收与恢复 |
| 工作台左侧 | 项目切换、任务列表、队列和运行提示 |
| 对话主区 | 目标、计划、消息、工具活动、待处理事项、成果摘要 |
| 资料侧栏 | 文件、变更、预览、记忆、扩展、协作与检查 |
| 任务头部 | 模式、执行器、模型、Auto／Ask、状态、阶段与预算 |
| 输入区 | 目标、附件、普通补充、立即纠正及停止 |
| 设置 | 账户长期指令、项目约定、扩展、记忆、执行及资源配置 |

当前状态优先展示，历史错误、调试细节和检查证据可按需展开。窄屏允许折叠区域，首版仍以桌面浏览器体验为主。

## 10. 资源、数据与安全要求

- 用户、项目、协作者与原生配置按明确范围隔离，文件与预览访问均进行身份校验。
- 对项目资料中的指令保持不可信处理，不能据此提升权限。
- 支持上传、解压、存储、并发、轮次、动作、时长和费用预算；达到限制时保留已有成果并说明原因。

## 12. 指标与发布门槛

质量指标包括必要条件通过率、有效交付率、继续修改成功率、异常恢复结果、阶段退回原因。效率指标包括执行耗时、用户等待、人工介入、工具调用及交付总成本，均计入失败执行与协作消耗。

按研究、数据、代码等任务类型统计；用户明确要求的人工验收不计为 Agent 失败。

发布前完成固定样本与异常场景验证，确认执行器兼容、权限、恢复和数据边界；数值目标在获得基线后制定。当前不声明未测量的成功率、成本或性能提升。
