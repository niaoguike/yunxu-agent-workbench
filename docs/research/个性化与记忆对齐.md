# 个性化与记忆对齐 Cindy

基准提交：`a5bd13c69b9f984ebee5fe32c737e489b6ab47dc`。以下区分帮助说明、Agent 提示策略和实际执行代码；未运行上游，不把提示策略视为每次模型都会遵守的保证。

## 核验事实与产品决定

1. **长期指令由用户显式配置。** 帮助页 `Custom instructions`（L7–13、27–32）说明：个性化文本最多 8,000 字符，追加到系统提示尾部，新任务生效，按本机登录账户保存、不跨设备同步。保存端 `getUserPrompt/setUserPrompt`（L51–67）实际读写按 owner 分隔的 localStorage，`setUserPromptOwner`（L39）切换归属。两个 system-prompt-append.ts 仅导出静态追加文本，不能用作 userPrompt 动态注入的执行证据；实际 IPC 到启动装配仍待核验。产品采用账户级「长期指令」，在云端保存并对新任务注入；界面显示当前任务是否已加载最新版。验收：保存后新任务遵循语言偏好，已运行任务显示旧版本；另一账户不可读取。
   [固定来源 personalization.md](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/help-knowledge/personalization.md#L7)

2. **自动记忆策略没有要求逐条征求确认。** `system-prompt.md` 的 When to save / How to save（L9–36）要求发现值得未来复用的持久信息就调用写工具；用户说“记住”也是保存信号，明确触发后写入并简短回应。执行端 `MakerMemoryStore.write`（L174–177）进行作用域检查后直接写入，没有逐条确认参数。不能据此排除上游其他授权层，但不能把“每条先确认”说成这里的默认策略。产品对齐自主记忆，提供可见的新增记录、编辑、删除和关闭入口；不增加每条确认步骤。验收：用户表达稳定偏好后产生可查记录，并在新任务复用。
   [提示策略](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/system-prompt.md#L9)；[MakerMemoryStore.write](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/store.ts#L174)

3. **偏好、反馈、项目约束是分类，不代表账户级跨项目共享。** 提示（L11–24）定义 user、feedback、project、reference 四类；feedback 必须解释 Why 和 How to apply；不保存临时进度、已有 AGENTS.md 内容、源码结构和原样工具输出。该提示同时说明记忆按 workdir 共享，不能因 user 类型就推断所有项目可读。产品保留四类，项目记忆以项目 ID 隔离；账户长期指令独立于项目记忆。人格、语气由长期指令明确配置，不由模型偷偷推断成不可编辑的人格档案。验收：项目 A 的约束不流入 B；明确的账户长期指令可应用于两者。
   [分类与禁止保存项](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/system-prompt.md#L11)

4. **索引用于发现，详情按需读取，关键词检索不是向量召回。** 提示（L30–51）要求写前检查已注入的 MEMORY.md，已有条目先读再更新，按文件读取详情，以 FTS5 检索关键词。`MakerMemoryStore.search`（L243–250）调用 FTS；`getIndex`（L154–161）读索引并复核作用域。产品在任务启动注入项目记忆索引，正文按需检索；修改与新增保持去重。验收：两个任务可复用同项目偏好；同名更新不产生重复记录；检索结果不能跨账户。
   [工具使用策略](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/system-prompt.md#L30)；[MakerMemoryStore.search](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/store.ts#L243)

5. **审查返回建议，不自动落实删除合并。** 提示（L47）明确 memory_review 仅给建议；`MakerMemoryManager.runReview`（L900–959）构造审查请求，检查模型路由，返回 suggestions。产品对齐：可发起整理，展示建议与执行后的变更记录；审查失败保持原记忆。验收：审查模型不可用时可正常查看已有记录，且不会清空或覆盖记忆。
   [MakerMemoryManager.runReview](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/manager.ts#L900)

6. **不能把压缩前自动写入当作已完成能力。** `MemoryFlushController.onUsageUpdate`（L68–90）只记录阈值命中，`onCompactBoundary`（L97–107）重置标记；此实现没有注入模型轮次或保存调用。产品首版依赖工作过程中按价值写入；若另做压缩前抢救，需要作为新增能力实现和验收，不能宣称复刻现成行为。验收：压缩阈值命中不会被界面误报为已保存全部对话；任务进度仍由任务记录承载。
   [MemoryFlushController.onUsageUpdate](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/flush-controller.ts#L68)

7. **关闭、忘记与换模型分别处理。** `MakerMemoryManager.enable/disable`（L443–498）切换统一记忆并返回 next-session，开启时关闭原生记忆，关闭时不恢复原生记忆；`resetWorkdir`（L734–736）可在禁用后清理项目记录。`runReview` 的模型路由与 `write`（L965–968）是独立链路。产品提供关闭记忆、新任务生效说明、删除单条、清空项目记忆；换模型不改变记忆所有权，不承诺运行中热更新注入。验收：关闭后仍能删除历史；清空 A 不影响 B；换可兼容模型后新任务仍使用同一项目索引；不同引擎上线前独立验证工具和提示装配。
   [开关实现](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/manager.ts#L443)；[resetWorkdir](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/memory/manager.ts#L734)

保存端源码：[userPromptStore.ts / getUserPrompt、setUserPrompt](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/renderer/lib/userPromptStore.ts#L51)。

## 实施边界

本项目应实现可写、可检索、可管理的项目长期记忆，与账户长期指令并存。云端账户同步、稳定项目 ID、记忆变更可见性是本产品决定，不能说成 Cindy 桌面端默认行为。仍需补齐长期指令的源码装配链、MCP 工具授权层和各执行引擎的新任务注入测试；这些缺口不影响以上存储与提示策略事实，但限制了“所有引擎行为完全相同”的承诺。
