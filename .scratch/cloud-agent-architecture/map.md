# 云端 Agent 工作台技术决策地图

Type: map
Labels: wayfinder:map

## Destination

基于当前 PRD v0.4、领域词汇表和已有源码调研，收敛出可以交给 `/to-spec` 综合为实施规格的完整技术方案。地图完成时，执行器适配、双模式状态与人工确认、工作空间、扩展、记忆、协作、成果、接口和验证方法都有可追溯决定，不再沿用相互冲突的历史候选。

## Notes

- 建图与两项基础研究已完成，后续按依赖推进决策；暂不实现平台，不代替用户回答 HITL 决策。
- 依据：[PRD](../../docs/PRD.md)、[领域词汇表](../../GLOSSARY.md)、[调研索引](../../docs/research/README.md)。旧技术方案是历史候选，不能当作已批准架构。
- 已确认：平台云端执行、长期项目、多任务、自由/需求开发双模式、阶段 Skill、人工参与、工具扩展、个性化与项目记忆、持久协作者与临时子 Agent。
- 当前执行路线已改为 Python 平台复用 Claude Code/Codex loop，见 ADR-0002；原生循环方案与 ADR-0001 已被取代。平台仍拥有业务流程及授权，不将执行器完成等同于需求完成。
- 沿用用户偏好：完整前置设计、按项目适配技术栈、控制工程复杂度；事实由研究取得，技术取舍集中呈现，不逐项询问可自行核实的细节。
- 目的地不要求实现代码或生成实施工单。地图清晰后进入 `/to-spec`，再由 `/to-tickets` 拆实现切片。
- 每次工作读取 wayfinder；HITL 读取 grilling 与 domain-modeling；research 读取 research；设计模块接口时使用 codebase-design。原型只有在具体问题需要运行证据时才产生。
- 本地约定：子票在 issues/，Type 决定方法，Status 为 open/claimed/resolved，Blocked by 引用本目录编号。最小编号的 open、未领取且依赖全部 resolved 的票构成可领取项；同一轮可并行研究独立问题。
- 地图只保存决策索引；答案写入对应票的 Answer，并链接证据文件。未决票通过扫描 issues/ 找到，不在地图重复列出。
- 当前仓库没有初始提交和远程仓库。研究采用本地文件快照与来源链接保存在本目录 research/，不虚构研究分支或已推送记录；后续如需要跨工作区移交，再按实际 Git 基线处理归档。
- 单个工作会话只手工解决一张 HITL 票；研究票可并行完成。建立地图不代表 PRD 的全部推荐参数已被批准。

## Decisions so far

<!-- 仅追加已解决票的名字、结论摘要与链接；研究结论不等于路线已获批准。 -->

- [核实执行内核候选的实际能力](issues/01-runtime-capabilities.md)：三类路线均需平台承担业务状态、工具幂等和云端隔离；能力矩阵已具备，最终路线仍待选择。
- [核实云端执行与预览环境的能力](issues/02-cloud-execution-capabilities.md)：文件持久化、进程快照和预览鉴权是不同能力；自管增强隔离与托管沙箱的边界已核实，未进行运行测试或路线定案。
- [选择执行内核与适配边界](issues/03-execution-kernel.md)：采用 Python 平台 + Claude Code/Codex 执行器适配，复用原生 loop；平台掌握阶段、确认、权限与协作，LangGraph 仅为外层编排候选。

## Not yet specified

- 执行适配器选定后，所需的运行验证细节、兼容性测试和可能的替代接入，需根据实际能力再细化。
- 扩展运行时确定后，若遇到未预见的协议、权限或取消语义，应新增精确问题，而非假定所有工具行为相同。
- 具体性能、质量与成本目标需要评测基线；PRD 的初始配额是候选值，不代表已测容量。
- 模式切换、过期确认与并行写入若仍无法从状态定义达成共识，再将精确疑问转为原型票。

## Out of scope

- 实现平台、部署服务、配置真实用户凭据、付费购买服务或公开发布。
- 本地执行端、多设备桌面控制、SSH、多用户团队、公开插件市场，以及首版排除的外部发送、推送和部署。
- 将已有源码局部行为误称为云端多租户安全或持久恢复的运行证明。
- 在决策尚未完成时直接编写实施规格、生成实现工单或重写全部技术方案为已定稿。
