# 工具扩展对齐研究

基准：makecindy/cindy `a5bd13c69b9f984ebee5fe32c737e489b6ab47dc`。本页区分执行代码事实、类型契约与本产品建议；不是上游完整安装链已验证的声明。

## 源码证据

1. `GhostToolDecl` 是声明式工具描述（name/description/parameters），接口旁契约要求在会话建立时按已安装且启用的插件快照提供工具，而不是运行中随意增删。[manifest.ts:203–216](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/plugin-protocol/src/manifest.ts#L203-L216)。此处为契约证据，实际会话装配链尚待追踪。
2. `GhostNodeNeeds` 声明包内入口、协议（含 MCP stdio）、生命周期和额外入口；注释明确本地 Node 有系统用户权限，不能当作安全沙箱。MCP 是接入协议，插件是可安装能力包，不能互换命名。[manifest.ts:286–324](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/plugin-protocol/src/manifest.ts#L286-L324)。
3. `GhostNodeSecretBinding` 将凭据绑定到方法及入口；契约说明由宿主保险库临时注入，Worker 收到明文仍可能泄露。因此“存入保险库”不等于插件永远看不到秘密。[manifest.ts:265–284](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/plugin-protocol/src/manifest.ts#L265-L284)。实际注入实现尚未验证。
4. `validateGhostManifest` 对 `skill.items` 检查安全相对路径、名称、描述和重复项。Skill 是交给 Agent 的指令资源，不能套用插件执行沙箱的安全承诺。[manifest.ts:3500–3587](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/plugin-protocol/src/manifest.ts#L3500-L3587)。文件前部注释还明确捆绑 Skill 可全局生效，工作目录停用插件不会自动隐藏 Skill；这是应明确提示用户的上游差异。
5. `PluginRegistry.isEnabled` 实际实现：基础工具始终启用；机器级工具读全局配置；普通工具先项目配置、再用户默认、再产品默认。未知 ID 返回 true，云端产品不建议复制这个默认。[plugin-registry.ts:61–91](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/maker-host/plugins/plugin-registry.ts#L61-L91)。此 registry 构造器载入内置插件，不能据此证明全部第三方插件复用同一链路。
6. `install` 调用下载器时传入服务端的 SHA-256、大小及上限；下载失败映射为校验/下载错误。同名目录未给 force 时返回冲突；解压先进入 staging，并限制条目数、路径与总大小。[installService.ts:620–721](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/skillhub/installService.ts#L620-L721)。哈希校验证明下载一致性，不证明内容安全或作者身份。
7. `install` 在最终切换前调用 `remoteGuard.beforeCommit()`，替换旧目录后保留备份，备份失败会尝试回滚文件及 registry。[installService.ts:723–938](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/skillhub/installService.ts#L723-L938)。更新可借同名替换机制完成；没有验证独立自动更新入口。
8. `uninstall` 与 `uninstallLocked` 持有安装锁并检查当前用户、来源身份；外部导入只移除链接；先写恢复记录，再移入系统回收站，后续清理可重试。[installService.ts:993–1341](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/skillhub/installService.ts#L993-L1341)。云端应迁移其可恢复事务思想，而非依赖桌面回收站。

## 可落 PRD 的产品机制（本产品建议）

- 扩展中心统一发现插件、MCP 连接和 Skill，但详情明确类型。支持目录检索、查看源码与来源、固定版本；提供包上传和远程 MCP 地址接入。首版不承诺任意桌面插件原样可运行。
- 安装流程展示来源、版本、校验值、声明能力、执行位置和权限。支持用户主动安装第三方扩展，不限于平台预置工具；未经审核标记必须与平台审核状态分开。审核通过不等于用户已授权外部发送、部署等业务动作。
- 用户默认决定新项目的初始偏好，项目显式覆盖决定本项目启用状态；提供“恢复默认”。安装、启用和连接凭据就绪是三个独立状态，页面解释最终生效值及来源。
- 云端插件代码在租户隔离执行环境运行，限制网络出口、文件挂载、资源与生命周期；远程 MCP 经平台连接器访问；桌面 Node、窗口、文件选择器能力标注不兼容，不静默映射成云端权限。
- 凭据按用户或项目绑定，只给获准连接和调用范围；展示未配置、有效、过期、撤销状态，支持重连及删除。工作空间文件、日志、模型上下文不写入明文。会接收明文的第三方服务需明确披露。
- 扩展版本、权限和工具清单在任务启动时形成快照，当前任务提示“下次启动生效”，用户可重启应用新配置。撤销凭据和紧急停用在执行入口立即阻断后续调用；不能只隐藏工具名称。
- 更新先展示版本与权限差异，新权限重新授权；失败保持原版本可用。卸载撤销后续调用、清理注册及连接，保留用户产物，说明凭据是否同时删除；提供可恢复的卸载记录。
- Skill 在项目明确启用，并展示其会改变 Agent 行为、可能使用任务已有权限。不要沿用上游“项目停用插件但捆绑 Skill 仍全局有效”的隐含关系。

## 未知与验证边界

未验证第三方 `.cindy` 插件安装/升级/审核 UI、SkillHub 搜索排序、作者签名认证、远程 MCP OAuth 完整链、运行任务热更新、平台后台安全审核。manifest 的声明和注释不能替代实际宿主执行证据。上游本地 safeStorage、symlink 与回收站均需云端替代设计。

## 验收建议

1. 同一扩展可在项目 A 启用、项目 B 停用；详情可解释继承与覆盖，不出现 Skill 偷渡。
2. 安装损坏包、路径穿越包、超大解压包均失败，旧版本和已有用户资料保持可用。
3. 扩展更新新增网络域名或凭据范围必须再次批准；未批准维持旧版本。
4. 正在运行任务保持版本快照；新任务使用新版本；紧急停用后在途后续工具调用被拒绝并可解释。
5. 未配置/过期/已撤销凭据不给 Agent 明文；日志和错误不泄露密钥。
6. 卸载与并发更新不会互删目录；中断后可恢复；其他项目和其他租户不受影响。
7. 安装或启用扩展不会自动授权发邮件、发布网站、部署或其它外部业务写操作。
