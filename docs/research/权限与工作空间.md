# 权限与工作空间源码调研

基准：Cindy `a5bd13c69b9f984ebee5fe32c737e489b6ab47dc`。阅读本地固定提交的 `session.ts`、`maker.ts`，并补读桌面宿主权限审核、工具审批及代码任务工作区与清理实现。本稿只把实际读取的消费代码作为事实，不把接口能力当作已实现的隔离保证。预览与成果另见专项笔记。

## 1. 自动执行需要逐动作授权判定

**代码事实**：`Session.reviewHostPermissionAction` 对权限切换中、关闭中、计划模式返回 block；bypassPermissions 返回 allow；其他非 auto 模式返回 ask；auto 委托底层审核，缺失或异常降级 ask。审核结束再次比较权限与计划 generation、停止状态，旧结果失效返回 block。[session.ts L1831-L1898](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/session.ts#L1831-L1898)。这是 Host 动作路径，不能据此断言所有工具均调用此函数。

**本项目建议**：需求明确直接执行项目范围内操作，内部保留 allow/ask/block 三态；自动审核不可用不应自动放行。首版不开放第三方登录或对外发送、提交、部署能力。

**验收**：审核过程中用户收紧权限，旧 allow 不执行；审核异常时进入待确认或明确阻止。

## 2. 审批和同步提问是等待中的任务，不是成功结束

**代码事实**：构造器把 handle 的 InteractionResolver 接到 `runHostInteraction`；没有宿主 listener 时权限默认 deny，问题返回空答案。`runHostInteraction` 增加等待计数、通知生命周期观察者并 await resolve，finally 清理等待状态；异步问题直接 resolve，不挂起同样的生命周期。[构造器 L643-L657](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/session.ts#L643-L657)、[runHostInteraction L2314-L2340](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/session.ts#L2314-L2340)。

**本项目建议**：把“需要补充信息”和“需要确认操作”作为任务等待状态；回答后续接同一任务。界面连接缺失不能等价于用户同意。

**验收**：任务出现确认卡后停止该动作；用户拒绝不会执行；确认完成后等待标记清除。刷新后恢复卡片的持久化机制仍须本项目自行设计，本轮未证实参考实现。

## 3. 文件访问目录有能力差异，目录参数不等于安全隔离

**代码事实**：`setExtraDirs` 与 `setWritableDirs` 检查会话活跃和 provider capability，再调用 handle；都不写数据库，持久化由 Host 协调。[session.ts L2192-L2219](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/session.ts#L2192-L2219)。本轮未取得桌面 file-access 宿主与 adapter 实现，不能证明路径穿越、符号链接、进程网络或跨项目隔离。

**本项目建议**：项目拥有云端工作空间，任务共享项目资料；运行时由平台强制限定项目路径，不只给模型提示。多个任务同时写同一文件时需要可见冲突处理。

**验收**：任务能读本项目材料；不能通过绝对路径、相对路径或链接读另一项目；两个任务编辑同一文件时不静默覆盖。以上是建议验收，非已证实参考行为。

## 4. 回退必须展示能力和实际覆盖范围

**代码事实**：`previewRewindFiles`/`commitRewindFiles` 检查 rewind capability 和 handle 方法；提交要求活跃且没有 turn、Host lease、权限切换等进行中，否则抛 `SESSION_RUNNING`；实际工作委托 adapter。[session.ts L2222-L2293](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/packages/maker-core/src/session.ts#L2222-L2293)。代码注释区分 Claude SDK checkpoint 与 Codex thread rollback，但未读取 adapter，不能确认各自恢复文件的完整范围，更不能宣称任意 shell 副作用可撤销。

**本项目建议**：首版明确区分停止任务、重试任务和恢复文件版本；只对已保存快照覆盖的项目文件承诺恢复，运行中先停止再恢复。

**验收**：恢复前展示受影响文件；运行中拒绝恢复；恢复不声称撤销已发生的网络请求。项目共享资料被别的任务修改后的恢复策略必须单独确定。

### 5. 自动审核是模型分类加确定性前置守卫

**代码事实**：`createAutoPermissionReviewer` 在没有用户意图、没有经宿主验证的 delegatedTask 时，直接 block 非 read 动作；超长动作、提示构造失败、分类重试耗尽返回 null，而非 allow。提示要求把输入字符串当作不可信数据，将常规任务操作、严重对外影响、critical 风险区分；这些风险规则属于分类提示，不是等价的硬编码安全保证。[auto-permission-reviewer.ts L123-L248](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/maker-host/auto-permission-reviewer.ts#L123-L248)、[L325-L447](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/maker-host/auto-permission-reviewer.ts#L325-L447)。

**建议与验收**：默认直接执行仍需绑定用户目标和项目范围；无用户目标的主动写入必须阻止；分类服务故障不得当作已授权。

### 6. 工具风险看实际内层动作，不只看服务名字

**代码事实**：`getDesktopMcpToolApprovalPolicy` 使用精确只读工具名单、经审查服务名单和聚合 payload 解析；浏览器 recipe、切换用户浏览器、上传、导入、连接桥均转入逐次会话审批；最后可信服务 auto-approve，其他 prompt。这里的 prompt-each-time 是避免复用服务级授权，仍由 Auto/Ask/Full Access 模式决定自动审核或询问，不能解读成必然人工确认。[mcp-tool-approval-policy.ts L202-L318](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/maker-host/mcp-tool-approval-policy.ts#L202-L318)。

**建议与验收**：首版将第三方登录和对外发送、提交、部署从可调用工具中排除；不要只靠审批弹窗约束。聚合工具新增危险内层动作时不得继承一次只读调用的授权；上传应被单独识别。

### 7. 独立 worktree 是代码制作任务机制，不是通用云端沙箱证明

**代码事实**：`createCindyMakeWorktree` 按 runId 从个人基线分支创建独立任务分支和 worktree；已有目录须非符号链接、分支正确且 git common directory 属于源仓库。重试可复用同一分支；本模块另有依赖安装阶段。[taskWorkspace.ts L39-L151](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/cindy-make/taskWorkspace.ts#L39-L151)。其适用域是 cindy-make，不能外推全部任务或进程隔离。

**建议与验收**：本产品以项目共享资料为默认；代码任务可使用独立修改区，成果显式应用回项目。两个任务编辑同一基线应保留各自修改；伪造目录、错误分支不得被当作可复用任务环境。

### 8. 归档、完成回收、丢弃具有不同文件后果

**代码事实**：`manageCindyMakeWorkspace` 对 archive 立即返回 false，不授权删目录；delete/end 走 discard。非 discard 要求已有 integrated 内容与当前文件匹配，或工作区干净且任务分支已是个人分支祖先，否则保留；关闭任务本身不整合文件、不创建提交。删除前核实托管路径、符号链接、worktree 注册与所属仓库；end 保存历史 ref，之后移除 worktree 和分支。[taskCleanup.ts L33-L211](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/cindy-make/taskCleanup.ts#L33-L211)。本轮未读取“整合”动作实现，不能声称具备自动合并冲突解决。

**建议与验收**：PRD 分开表述归档任务、应用成果和删除修改区。归档保留文件；完成任务不隐式应用代码；未应用或又被修改的成果不静默回收；明确丢弃需展示会损失的内容。

**修订后的未知清单**：审批卡刷新恢复与持久化、通用任务的运行时沙箱与网络隔离、跨任务共享资料冲突策略、adapter checkpoint 完整覆盖范围、显式整合动作的合并与冲突处理仍未证实。
