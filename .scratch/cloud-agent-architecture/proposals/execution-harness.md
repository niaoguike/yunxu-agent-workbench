# 执行器复用与平台编排方案

状态：accepted。2026-11-03 用户在明确两种 loop 架构区别后要求“跟cindy对齐”。本方案取代[原生循环方案](execution-kernel.md)，对应[执行内核决策](../issues/03-execution-kernel.md)。具体存储、队列、云端执行环境和原型验证继续由后续决策处理。

## 执行路线

- 平台后端保留 Python/FastAPI，前端保留 React/TypeScript。
- 首批执行器为 Claude Code 与 Codex，先完成一条 Claude Code 端到端路径，再独立接入 Codex。Claude Code 通过官方 Agent SDK 的 Python 接口接入；Codex 通过 App Server 的双向 JSON-RPC 接口接入。
- 执行器负责内层模型调用、动作决策、原生工具执行与上下文处理。平台不再实现替代这些执行器的模型—工具循环。
- 平台负责用户交付流程、状态、确认和资源政策。LangGraph 可作为外层阶段编排候选，是否采用留待状态决策，不直接套在每次原生工具动作之外重复驱动。
- 本方案对齐运行分层，不要求照搬桌面宿主、设备连接或其全部代码。执行器部署在平台管理的云端环境，原先的云端产品定位不变。

## Module 职责

| Module | 平台职责 | 执行器职责 |
| --- | --- | --- |
| 任务编排 | 模式、阶段、待办、需求版本、人工确认与最终验收 | 接收本轮目标、已授权上下文和能力配置 |
| 执行器适配 | 创建/恢复会话、发送输入、审批回传、停止、事件归一和能力探测 | 自己的 Agent loop、原生会话与工具行为 |
| 工具与扩展管理 | 扩展安装、连接配置、项目作用域、凭据、权限政策和撤销 | 经适配配置调用原生工具与 MCP |
| 记忆与个性化 | 长期指令、平台项目记忆、审查和可见变更 | 通过对应装配或工具入口读取和使用 |
| 协作管理 | 持久成员、职责、指派、汇报、独立权限、总预算和修改区 | 每个成员各自运行一条原生执行会话；临时子 Agent 由原生能力承载 |

平台业务会话与执行器 session/thread 不是同一个标识。保存执行器类型、版本、认证作用域、工作空间、原生会话标识及本轮 turn 映射；执行器会话建立并确认前，不宣称它已可恢复。

## 最小 Adapter Interface

1. 查询能力与状态：可用模型、认证就绪、持续会话、立即纠正、审批、MCP、Skill 装配、原生子 Agent 与上下文处理的实际支持情况。
2. 创建/恢复：绑定正确工作空间和配置快照，返回真实原生会话标识；不能使用另一执行器的标识继续。
3. 投递输入：普通消息的持久队列由平台管理，空闲后投递；立即纠正只有成功回执才显示已进入当前轮次。
4. 响应交互：将提问或工具审批转成平台卡片，再将有效决定发回对应执行器请求。
5. 请求停止与关闭：区分停止当前轮次、关闭运行进程和删除持久任务。停止请求回执不等于终态确认，也不承诺撤销外部副作用。
6. 读取标准事件：公开文本、原生工具活动、待交互、用量、轮次终态和错误均关联平台与原生执行标识；保留排障所需的原生事件类型及版本，不暴露私有推理和凭据。

这些 Interface 供调用者和行为测试共用。Claude Code 与 Codex 分别实现真实 Adapter，不创建假设所有执行器行为完全相同的接口字段。

## 双模式与阶段 Skill

自由模式将用户目标、选定方法和项目上下文交给执行器，持续处理其事件与必要交互。

需求开发模式由平台选择当前阶段及阶段 Skill，把阶段目标、输入、约束与退出条件装配给执行器。执行器返回后，平台检查阶段成果和确认条件，再决定是否进入下一阶段；进程退出成功或轮次完成不代表整项需求已验收。

阶段 Skill 是可复用的方法资源，其装配由适配器按该执行器的真实机制完成。缺少必需工具或无法加载当前版本时明确阻塞，不以“提示里提到 Skill”冒充原生加载成功。

## 能力差异与切换

- 执行器和模型分开选择。模型列表、供应商和配置必须在该执行器支持范围内，目录出现某名称不等于已验证账户访问权。
- 同执行器更换模型也要遵守其会话规则。跨执行器默认创建新原生会话，并显式交接目标、约束、成果和必要摘要，不宣称任意原生历史或内部状态可无损迁移。
- 原生子 Agent 与平台持久协作者分别标识。主 Agent 和成员可选择不同执行器，但都使用本项目授权与共同预算。
- 撤销平台能力时，必须阻止后续原生工具或 MCP 调用，不能只从 UI 隐藏。需要验证原生自动放行规则不会绕过平台强制限制；不能实现执行前约束的能力保持不可用。
- 平台记忆是可管理的共享事实来源。执行器原生记忆、配置与扩展状态须有明确作用域，不与其他用户或项目混用；与平台记忆的重叠和关闭行为需要逐执行器验证。

## 云端运行与恢复限制

- 执行器二进制/SDK、配置目录、会话记录与模型认证在云端独立管理，不能默认复用开发者桌面的现有登录。
- 模型认证与 MCP 凭据分开配置。普通项目命令不得取得平台全局凭据；原生 shell、执行器进程与秘密的隔离需要在云端执行环境决策中验证，不能因使用现成执行器就视为已经安全。
- 原生 session/thread 恢复仅证明其支持的会话恢复。文件备份、工作区重建、平台待确认状态、指派去重与预算恢复仍由平台协调。
- 原生工具效果不明时先核对再重试；文件版本恢复不代表运行进程和网络操作也被撤销。
- 用量和工具动作的可观察范围按执行器能力展示。无法获得的部分标估算或未知，不能用平台没有观测到来推断没有发生。

## 验证条件

- 每个 Adapter 都覆盖真实会话创建、继续、工具文件产物、交互响应、停止终态及重连恢复；事件夹具只验证平台状态机，不替代真实执行器集成。
- 通过原生工具和 MCP 分别验证拒绝、参数变更、撤权与凭据边界，避免只测试一条可控的自定义工具路径。
- 对即时纠正不支持、已结束轮次、失效 session/thread、认证未就绪和版本不兼容给出明确结果。
- 主 Agent 与成员使用不同执行器时，验证指派、汇报、总预算和版本交接，不用一个引擎成功证明所有引擎兼容。
- 本次只完成文档和静态接口核查，未启动执行器、配置凭据或调用真实模型。
