# 云序 Personal Agent 产品对齐路线

日期：2026-11-21。范围：以 Dots 为持续责任与委派体验基准，Muse 为个人上下文与隔离权限基准，Grok Bot 为主助手管理专业协作者的体验基准。对齐公开可观察能力，不声称拥有相同模型、内部实现或第三方授权。

## 产品骨架
账户主 Agent 是用户长期交互入口；项目是资料与执行容器；目标是有完成条件的承诺，责任是无固定终点的持续工作，关注项是等待条件成立再行动的订阅。一次对话可以涉及多个目标，目标可以跨对话推进。不能要求每次使用先创建项目和填写目标表。

## 交付顺序及验收
1. 修复现有 goals 骨架并补足权限、并发、幂等与测试；目标完成需证据。确认暂停与恢复不重复执行。
2. 建立账户主 Agent 身份、持久对话、个人工作空间和上下文装配；已有工作台任务作为可委派执行单元。验收跨会话记住用户明确授权的偏好，并可查看修改删除。
3. 增加责任/关注项和持久 sleep/wake；事件路由、目标复核、下一行动、派发意图与结果回流。验收用户离线时因新事件推进，重启后不丢失也不重复，失败预算到限停止。
4. 安全连接器：先邮件与日历，含 OAuth、撤销、增量游标、事件去重、读写范围、凭据代理和外部操作审批。验收新增邮件或日程变化驱动已有责任，未经允许不发送消息。
5. 持久云电脑与浏览器，包含独立登录态、实时查看、用户接管、暂停与恢复；执行域和凭据/权限域分离。验收无连接器网站的授权操作与失败回退。现有 Docker 开发执行不等价于此能力。
6. 个人主界面：主助手对话、今日动态、需要决定、进行中的责任、成果与电脑；支持渠道入口，随后补实时语音。用户无需进入项目就能交办，委派任务可查看和追问。
7. 接回持久协作者：专业职责、独立上下文、结果回报、主助手汇总；预算及权限不能因委派扩大。验收两项专业工作并行，用户从主助手获得汇总和证据。

## 核心验收场景
“帮我组织下周演示”：对话建立目标，读取授权日历和资料，委派准备材料，收到参与人变化后调整计划，必要时请求用户决定，材料与时间确认后结束目标。
“持续关注客户邮件”：作为责任持续存在，收到新邮件后检索相关背景、起草回复，审批后发送，失败保留状态；不能每轮都要求用户点击恢复。
“关注某商品价格”：条件事件触发通知，去重和安静时段有效，无新信息不消耗无限模型调用。
