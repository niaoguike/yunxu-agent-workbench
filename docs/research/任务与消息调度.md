# 任务与消息调度：Cindy 源码研究

基准：makecindy/cindy，提交 `a5bd13c69b9f984ebee5fe32c737e489b6ab47dc`。本笔记区分已读源码事实、产品建议与尚未核实的行为，不把接口存在当作完整 UI 行为证明。

## 已确认事实与产品规则

1. **源码事实：队列不是聊天记录的临时数组。** `agentInputQueueSnapshots.ts` 的 `saveAgentInputQueueSnapshot` 在队列变化后保存单行快照；写入按任务串行，另有 `awaitAgentInputQueueSnapshotPersistence` 暴露持久化失败。超限时去除内联 base64，仍超限则保留旧快照并报错。**本产品建议：**收到、已保存、正在执行分别表达；只有落盘成功才承诺刷新后可恢复。材料使用持久文件引用，避免把大附件塞入队列。
   - [源码：快照写入与等待，L91-L136、L226-L268](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/localDb/agentInputQueueSnapshots.ts#L91)
2. **源码事实：取消需要持久化意图，且队列与历史以 clientId 衔接。** `flushCancellations` 周边注释明确处理取消与并发入队的竞争；读取 ownership 时先读快照再读历史。**本产品建议：**每条用户输入有稳定消息 ID，重试与恢复复用该 ID；取消成功不得因重启重新执行。
   - [源码：取消与 ownership，L67-L190](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/localDb/agentInputQueueSnapshots.ts#L67)
3. **源码事实：待执行消息可编辑、取消、移动；正在投递时不可修改。** `createSessionQueueControlService` 先检查 consumingClientIds，编辑必须保留原 clientId，失败后重新分类竞争结果。**本产品建议：**首版保留队列查看、编辑、取消；排序可延后。投递边界返回明确结果，不能先在 UI 显示取消成功。
   - [源码：服务，L66-L197](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/maker-ipc/sessionQueueControl.ts#L66)
4. **源码事实：steer 不保证成功送入当前轮次。** `createQueueReorderAdapter` 检查活动轮次、sameTurnSteer 能力、远程宿主和发送锁；结果可能保持排队，理由包括 NO_ACTIVE_TURN、STEER_UNSUPPORTED、INPUT_BOUNDARY_BUSY、STEER_UNCERTAIN。**本产品建议：**运行中输入默认作为后续消息排队，另提供“立即补充要求”；失败保持原位置并提示，不能静默丢失或宣称已生效。
   - [源码：结果类型与适配器，L21-L33、L241-L276](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/maker-ipc/sessionQueueControl.ts#L241)
5. **源码事实：恢复载荷会校验和清洗。** `loadAgentInputQueueSnapshot` 丢弃损坏 JSON、过滤畸形行，并清除旧快照中受信 session reference 正文；不是无条件执行数据库内容。**本产品建议：**恢复前检查材料存在、任务状态和权限；损坏输入标为失败，给用户可见的重发入口。
   - [源码：恢复校验，L370-L426](https://github.com/makecindy/cindy/blob/a5bd13c69b9f984ebee5fe32c737e489b6ab47dc/apps/desktop/src/main/localDb/agentInputQueueSnapshots.ts#L370)
6. **本产品建议：任务运行与任务组织状态分开。** 运行状态采用排队、执行、等待用户、完成、失败、已停止；归档属于组织状态。停止当前执行后暂停该任务队列，用户明确继续才消费后续消息。刷新页面不影响服务器执行；执行器重启后展示中断和可恢复项，未经幂等证明不得自动重放工具操作。
7. **本产品建议：创建、归档、删除各有独立语义。** 创建任务后先获得稳定任务 ID，再接收首条输入；项目材料共享、任务对话独立。归档保留对话成果且停止执行；恢复归档不自动重启。删除需要明确确认，删除任务自己的历史和结果引用；共享项目文件不能随任务删除。

## 风险与验收场景

| 风险 | 对应验收 |
|---|---|
| 入队成功但未落盘 | 注入存储失败，页面显示未保存并允许重试；重试不产生第二份输入 |
| 用户取消与执行器领取竞争 | 同时取消和领取，只出现“取消成功”或“已开始无法取消”；重启不复活已取消项 |
| steer 实际未交付 | 无活动轮次、发送锁占用和不支持 steer 时，消息仍在队列，提示具体结果 |
| 工具已生效但执行器崩溃 | 重启后不重复写文件或运行外部操作；显示中断以及已完成步骤 |
| 归档与恢复竞争 | 归档停止过程中恢复，不误删历史；恢复后不自动消费旧队列 |
| 共享材料被任务删除带走 | 两任务引用同一项目文件，删除其中一个后另一任务仍可使用材料 |

## 宿主实现补核：停止、恢复与投递

以下结论已读取 `.references/research-host/agent-input-coordinator.ts` 的实现语句，而非仅依据文件头注释。

- **源码事实：stop 并非无条件保留队列。** `stop`（L3060-L3162）只有 `keepQueue === true` 才保留；否则 L3078-L3088 清空 pendingQueue 并逐项调用丢弃回调。暂停还要求 `pauseQueue` 且存在待执行项（L3115-L3119）。共享任务会强制 keepQueue。因尚未核实 UI 调用传参，不能断言“用户点停止默认保留”。本产品仍建议明确采用保留并暂停，另设清空队列操作。
- **源码事实：停止完成不能等同 abort Promise 完成。** L3129-L3159 请求 abort，并用任务状态身份、generation 与 token 排除迟到回调；随后 reconcileAbortBoundary 核对供应商边界。旧停止回调不能修改新执行轮次。
- **源码事实：恢复暂停与用户停止暂停不同。** 恢复实现 L1718-L1729 在任务安静时合并恢复队列并置 queuePausedByRestore；若恢复时已有工作则不强制暂停。`enqueue` L1986-L1988 仅在显式输入标志及恢复暂停同时满足时解除暂停，普通 Stop 暂停不受此路径影响。`resume` L3175-L3192 明确解除暂停并唤醒 drain。产品验收需覆盖这两类暂停，不应都显示同一种无解释的“等待”。
- **源码事实：执行入口串行消费队首。** drain 门禁 L4938-L4955 检查恢复、暂停、abort、交互锁、steer、recovery 和执行边界；实际 L5064 移除队首，L5072-L5087 建立 activeTurn。说明普通 enqueue 消费路径是队列投递，不能把“排队”误写为自动 steer。但 UI 是否默认调用 enqueue 还是 steer，仍需 renderer 调用证据。
- **源码事实：发送 IPC 是事务适配器。** `registerMakerSessionSendHandler` L31-L62 校验 sessionId，附加主进程拥有的输入边界后委托 sendToAgentAccepted；它自身不决定默认队列策略。`enqueue` L1925-L1931 对重复 clientId 直接返回当前 projection，不重复入队。

## 证据边界与待核实链路

已读的是桌面主进程真实 queue control 服务及数据库持久化实现，超过仅查看 maker-core Prompt 接口的范围。`sessionCreateHandler.ts` 确实读取创建参数并在 abort 时关闭创建中的执行对象（L88-L130），但本次未完整核实 UI→IPC→创建服务、停止和重启恢复注册链路，因此不能声称 Cindy 已提供上述全部用户体验。

源码树已定位 `renderer/lib/messageService.ts`、`sessionRuntimeControl.ts`、`deferredRestartQueueWiring.ts`、`main/localDb/ipc/sessionRemovalOperations.ts`。网络随后持续出现 EOF。后续由共享快照补齐发送 IPC 与协调器正文，已确认上述分支行为；归档/删除的物理清理范围及 UI 停止具体传参仍未知，PRD 应采用明确产品规则，而不是把未知当成 Cindy 现成能力。
