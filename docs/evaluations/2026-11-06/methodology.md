# 方法、运行条件与结果边界

## 固定协议

数据集版本 1.0，执行与验收代码固化于提交 bda5bd3。主实验开始时基于 6f219c2 的工作区，metadata 如实标记 dirty_tree；新增元数据导出代码随后提交。任务材料、提示哈希、判分规则与循环轨迹标签在各自主运行前已确定。未使用网络搜索、外部业务数据或主工作台用户的项目。

主实验：3类任务 × 2策略 × 2轮，共12个任务组；每组时限300秒。每组新建项目、任务、原生会话和资料副本，项目记忆关闭。策略顺序按任务与轮次交替，不以成功或失败决定后续样本。协作策略恰好指派一名持久协作者承担实质任务，再由主任务回写并核验；它测试委派与集成开销，不测试多成员并行加速。

执行环境：Windows、Python 3.12.10、trusted-local、Codex CLI 0.166.0-alpha.6。已观测模型 gpt-6.1-sol，沿用本机原生默认推理配置，未锁定服务端模型快照或设置随机种子。原生风险审核仍生效。TestClient 直接访问真实 FastAPI 应用，随后经真实 worker 子进程和 Codex App Server 调用模型；不是浏览器点击耗时。

## 任务与外部判分

1. CSV：去重、状态标准化、非法金额过滤、Decimal 精度及客户分组。验收器比较固定预期 JSON，并检查输入未被改写。
2. 计费：修复浮点计算、折扣、舍入和非法输入处理。验收器在独立 Python 子进程执行19项未放入任务工作区的边界检查，并核验交付文件存在。
3. 资料核验：只用6条本地资料，识别旧价格、附加出口费用、地域约束与营销/事故证据冲突。验收器比较结论与数值，核对必要引用覆盖；不等同自然语言全文的专家质量评分。

成功必须同时满足平台 delivered、实验未超时、成果独立检查通过及执行策略遵循。单 Agent 不得创建持久或原生子 Agent；协作组要求恰好一名参与执行的成员，允许修复重派，不使用原生临时子 Agent。最终返回再调用独立验收器，文件检查正确但未完成主任务交付仍判失败。

## 干扰与限制

主实验内部按组串行。循环复核对照在 UTC 12:33:21～12:36:29 同期运行，和第一轮 CSV 协作样本重叠；第一轮 CSV 单 Agent 未重叠。该样本存在共享模型服务干扰，耗时与全样本中位数仅作运行观测，不能用于因果提速结论。后续主实验与600秒补充诊断不主动重叠。模型服务排队、缓存及本机其他应用未做硬件级控制。

两次重复远不足以估计开放任务成功率，也不支持统计显著性、P95或规模化吞吐结论。Token 按各原生会话最大累计值去重，跨主任务和成员求和。totalTokens 包含重复输入和缓存输入，不代表付费输入；实际账单不可得，不输出金额估算。失败/中断会话的末次 Token 通知可能不覆盖最后一段执行，故统一称已观测使用量。

## 循环治理对照

10条人工固定轨迹重复两轮，每策略20条：4种永久失败、4种明确授权的暂时重试、结果变化及重复成功各1种。固定策略到8次相同失败停止；自适应策略在3次失败后调用真实只读辅助模型，读取相同工具证据与任务意图。没有真实执行那些失败命令。

两策略均检出8/8永久失败；非循环误停分别8/12与0/12。真循环停止动作中位数分别8与3。自适应策略16次真实复核均成功返回、工具动作共0，复核耗时中位数11.648秒，已观测总 Token 199688。减少工具动作与降低总耗时是不同结论：工具很便宜时，额外复核可能增加延迟与消耗。

轨迹刻意包含永久错误与已授权重试来检查策略区别，不代表真实错误先验分布。两轮同轨迹不是20个独立业务任务。超时宽限、结论过期失效及复核次数上限另由协议/状态回归验证，本表不冒称已覆盖全部复核故障率。

## 可靠性故障注入

10批、每批20次相同逻辑请求，对比稳定 ID 与每次新 ID。使用真实 Collaboration、SQLite 事务及工作区代码，将调度出口替换为空操作，不调用模型。

稳定 ID 总计200次请求、10条逻辑指派，重复0；新 ID 基线200次请求、200条逻辑指派，重复190。后者包括排队消息，不能宣称190次真实重复执行已被避免。稳定 ID 策略额外覆盖10次数据库重开回执恢复、10次同键载荷冲突、10次并发文件修改拒绝和10次重复应用，共40/40项不变量通过。

## 失败分析与修复后补充验收

原生执行环境未继承平台虚拟环境的 Python 目录，导致任务内 python/python3/py 均不可用。Agent 如实报告测试未验证，平台拒绝交付并触发补修；部分计费代码虽通过外部19项隐藏检查，仍未完成整组交付，计为失败。另有资料核验成员把未来的主任务独立验收列入自身未验证检查，引发不必要的补修。

修复提交 b95273c：trusted-local worker 的 PATH 前置平台 Python 所在目录；明确成员只核验自身职责，不把主任务未来步骤混入成员交付，但自身未验证项仍须如实报告。进程级回归验证原生子进程继承该路径，协作回归验证成员获得检查边界指令。

主实验使用启动时已加载的原运行器及工作流类，12组保持旧配置；代码编辑不热更新该 TestClient 进程。补充实验使用新进程加载修复。

在主实验结束后，补充相同计费任务、每策略一次、600秒上限的新进程验收。输入和独立验收规则不变，但同时采用环境修复、成员检查范围修复及更高时限，不能将结果变化单独归因于预算或任一修复。结果单列，不替换主实验分母或混算两种条件。当前代码的重跑默认采用修复后环境，不应期待复现历史基线的同样失败分布。

运行原始事件、项目资料、数据库保留在忽略提交的 .data/evaluations。仓库 results.json 导出固定任务的检查结果、指标与成果哈希，并归档固定任务的代码/JSON成果；检查日志中的本机路径保留在本地，不导出原始对话、登录会话或认证配置。

判分更正 1.0.1：提示要求只用一名持久成员，并未禁止向同一成员再次指派修复。初版将指派条数误作成员数；更正为参与指派的成员去重数。原始 results.jsonl 不改写，导出记录保留 scoring_correction（如发生），主实验12组分数不变。

## 后续复验发现与 Unicode 修复

第一组补充（billing-600s）单 Agent 在241.922秒内完整交付并通过外部19项检查；协作组仍在600秒截止时未完成。该组首次成员执行出现 UnicodeEncodeError，随后触发修复重派。不能将这一组写成2/2通过。

循环监控使用 ensure_ascii=False 序列化工具输入，遇到孤立 UTF-16 surrogate 后进行 UTF-8 指纹编码会崩溃。改为与确定性保护器一致的 ASCII JSON 序列化，使非法字符被转义。回归以孤立高/低 surrogate 作为真实 Python 字符串，验证三次异常证据能安全生成复核请求。

第二组补充（billing-unicode-fixed）仅复验协作计费，独立新进程、全新项目、600秒上限；它不替换第一组补充失败。三组运行的修复条件不同，不混算总成功率。结果见 report.md 和各组元数据。

最终补充结果：Unicode 修复后的协作计费仍失败，约301.5秒结束；未完成成果回写。因此仅确认已完成评测与缺陷修复回归，不能宣称协作端到端验收通过。完整失败原因保留在 results.json 的 run_errors。

最后一轮 run_errors 明确为 usageLimitExceeded（模型额度耗尽），应标记为基础设施中断，不据此断言 Unicode 修复无效；修复后的协作成功复验尚缺证据。失败样本仍保留，不从分母删除。
