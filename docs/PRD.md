# 通用云端 Agent 工作台 PRD

> 2026-11-06：已整理为 [产品需求文档 v0.5](产品需求文档.md)，包含完整产品流程、Auto／Ask、当前版本边界与验收索引。本文保留为 v0.4 详细需求及 AC-01～AC-49 的历史基线；配额提案与开发版参数以整理版区分说明。

版本：v0.4，完整草案。在双模式、扩展、记忆与协作基础上，增加成熟执行器接入与能力差异规则。平台通过可选执行器完成实际工作，自由模式延续明确需求直接执行，需求开发模式采用阶段 Skill 和人工确认点；阶段成果仍由平台检查与用户验收。具体策略供整体评审，本文不代表相关能力已经实现或验证。

## 1. 产品目标

面向开发者和技术型个人用户，提供可长期使用的云端工作台。用户提交目标和材料，Agent 自主规划、调用工具并完成工作，交付能够查看、运行或下载的成果；用户可以了解进度、补充要求并继续修改。

核心收益是委托任务后获得成果。项目资料、任务历史和交付结果持续保留，用户无需为了后续修改重新整理全部上下文。平台以人工参与关键决策、Agent 自主推进已授权工作为共同原则，通过自由模式和需求开发模式满足不同的工作组织需要。

### 1.1 已确认的产品决定

- 通用工作台，研究、数据分析、脚本和软件原型都是应用场景。
- 项目文件和工具默认位于平台提供的云端工作空间，通过网页使用。
- 项目长期保留，同一项目可以连续开展多项工作。
- 每个项目有多个独立任务，每个任务有自己的目标、对话、进度和结果，共用项目资料。
- 自由模式中，需求明确时展示计划与默认假设后直接执行，关键缺失才询问；需求开发模式按阶段推进，在指定人工确认点等待用户决定。
- 首版支持公开资料研究、文件与数据处理、编写和运行代码、测试及应用预览。
- 首版不包含第三方网站登录操作、对外发送消息、提交代码或外部部署。
- 工具扩展提供发现、安装、配置和项目启停；个性化包括长期指令与自主项目记忆；Agent 协作同时支持持久协作者与临时子 Agent。
- 任务支持自由模式与需求开发模式；后者每个阶段预置 Skill，自由模式允许更高程度的工具、方法、模型和协作配置。
- 实际执行优先复用成熟 Agent 执行器，首批接入 Claude Code 与 Codex；平台独立管理任务、阶段、人工确认、权限、记忆、协作与验收。

### 1.2 产品成功标准

1. 用户从创建项目到启动第一项任务，不需要配置本地开发环境。
2. 用户能区分任务正在执行、等待自己、已停止、未完成和已完成。
3. 每次宣告完成都有对应成果和适用检查记录。
4. 关闭网页、环境休眠或执行异常，不会让已经保存的项目资料和成果无提示消失。
5. 用户可以在原任务中继续修改已有成果，历史交付仍能识别。

## 2. 典型用户与场景

| 场景 | 用户输入 | 交付结果 | 完成依据 |
| --- | --- | --- | --- |
| 技术研究 | 目标、比较维度、材料或公开链接 | 研究报告、来源清单、必要的对比表 | 要求覆盖，关键结论有来源，不能确认的信息明确标注 |
| 数据处理 | CSV 等数据及分析目标 | 清洗数据、图表、分析报告、可复查脚本 | 处理规则、统计口径与异常情况明确，关键计算可复查 |
| 代码任务 | 公开仓库或已有项目、修改目标 | 代码变更、运行说明、测试结果 | 约定功能检查通过，未运行检查明确列出 |
| 应用原型 | 功能描述、参考材料与素材 | 项目代码、受控运行预览、交付摘要 | 可启动、关键交互通过适用检查，不冒充公开部署 |
| 持续修改 | 指定现有成果及新要求 | 新版本成果、变更说明 | 新条件检查通过，旧交付记录保留 |

支持组合任务，例如读取数据、生成分析报告并制作展示页面。系统按实际可用能力执行，不要求用户先选择固定产物模板。

## 3. 范围

### 3.1 首版包含

- 注册、登录与个人项目管理；账户数据相互隔离。
- 空项目创建、文件上传、ZIP 导入、公开 Git 仓库导入。
- 项目文件查看、文本预览、成果下载和代码变更查看。
- 多任务、任务内连续对话、计划与进度、工具活动及待办提示。
- 任务级双模式、阶段 Skill、阶段成果、人工确认与退回修改。
- 搜索和读取公开网页，处理文件、执行代码、运行测试和开发应用。
- 受控静态内容预览和应用运行预览。
- 排队、执行中纠正、停止、继续、错误说明及部分成果保留。
- 扩展中心、插件与 Skill 安装导入、自定义 MCP 连接、凭据配置和项目级启停。
- 账户长期指令、项目约定、可读写和检索的自主项目记忆。
- 用户可见的持久 Agent 协作、临时子 Agent、成员模型与权限设置。
- 任务模型选择、协作总预算和资源限制。
- 执行器选择、认证就绪、原生会话继续及能力差异提示。
- 按需求检查成果，对失败项进行有限修复。

### 3.2 首版不包含

- 用户电脑执行端、远程桌面、SSH 接入、移动客户端。
- 跨用户团队共享、多人同时编辑、公开项目分享、公开发布与交易型插件市场。
- 私有仓库账号连接，以及自动发送、推送、发布、部署或支付。
- 未经兼容性与权限检查直接运行任意扩展；需要用户桌面或操作系统界面的插件原样运行。
- 永久在线的网站托管、完整云 IDE、用户交互式远程终端。
- 自动训练模型、自动发布自身生成的方法包。

平台可对任务内应用进行本地提交或保存点管理，但不向外部仓库推送。公开链接读取不包括获取其他人的受限资料。

## 4. 产品对象与关系

| 对象 | 产品含义 | 关系 |
| --- | --- | --- |
| 项目 | 长期开展一组相关工作的组织单位 | 包含工作空间、多个任务和项目设置 |
| 云端工作空间 | 平台提供的文件与工具环境 | 项目资料持久保留，计算可启动和休眠 |
| 任务 | 围绕一个目标的独立工作单元 | 包含对话、多次执行、成果与需求记录 |
| 执行轮次 | 一次用户要求触发的工作过程 | 有独立计划、活动、检查结果和资源记录 |
| 成果 | 明确交付给用户的文件、变更或预览入口 | 关联任务、执行轮次和具体版本 |
| 检查项 | 判断用户要求是否满足的可解释条件 | 关联需求与成果，有通过、未通过或未核实结果 |
| Skill | 可复用的任务方法 | 有适用范围、版本、状态和所需能力 |
| 插件 | 可安装和配置的能力包 | 可包含工具、方法与资源，有来源、版本和权限 |
| MCP 连接 | 访问一个工具提供方的连接配置 | 独立记录地址或启动配置、连接状态和凭据 |
| 长期指令 | 用户主动设置的持续行为要求 | 分为账户级偏好和项目级约定，区别于自动记忆 |
| 记忆 | 可供项目后续任务复用的持久信息 | 有分类、来源和版本，可自主写入并由用户管理 |
| 协作组 | 同一任务内由主 Agent 与持久协作者构成的工作关系 | 有独立会话、职责、指派与汇报记录 |
| 持久协作者 | 可再次联系和继续指派的 Agent 成员 | 保留独立会话，不等同于临时子 Agent |
| 任务模式 | 用户选择的工作组织方式 | 自由模式或需求开发模式，按任务记录 |
| 执行器 | 承接实际 Agent 工作与原生会话的执行引擎 | 与模型分开选择，按支持能力接入平台 |
| 流程阶段 | 需求开发任务中有输入、产出和完成条件的一段工作 | 关联预置阶段 Skill、阶段成果与确认记录 |
| 人工确认点 | 需要用户决定是否通过或修改的流程节点 | 绑定当前成果和版本，不等于工具授权 |

任务完成后继续发送要求，会创建新的执行轮次，保留原目标和变更记录。新的目标与原任务无关时建议新建任务，用户仍可自行决定。跨任务共享项目文件，不自动完整复制其他任务的对话。

## 5. 主流程

### 5.1 共同入口与执行

1. 创建或打开项目，导入必要材料。
2. 新建任务并选择自由模式或需求开发模式，描述目标，可指定文件、Skill、执行器及其支持的模型和预算。
3. Agent 判断信息是否足够：关键条件缺失时集中提问；非关键缺失说明默认假设。
4. 展示本次理解、主要步骤、预期成果和检查条件；自由模式按已有授权开始，需求开发模式进入当前阶段并遵守人工确认点。
5. 用户查看进度、工具活动、文件变更与预览，可排队补充、立即纠正或停止。
6. Agent 生成成果并执行适用检查；未通过的部分进行有限修复。
7. 结果区域展示完成情况、成果、检查证据、限制和后续操作。
8. 用户下载、查看或继续提出修改要求。

自动执行不能跳过必要授权。对用户本轮已明确提供的信息与授权，不重复询问。

### 5.2 双模式关系

| 方面 | 自由模式 | 需求开发模式 |
| --- | --- | --- |
| 主要用途 | 研究、处理数据、写脚本、探索和灵活开发 | 有明确需求、阶段成果和验收约束的软件开发 |
| 工作组织 | 由用户与 Agent 按目标动态选择步骤 | 按预置流程阶段推进，允许有记录地回退和重做 |
| Skill | 可自由选择、组合或不用固定方法包 | 每阶段有默认 Skill，记录实际版本与产出 |
| 模型与协作 | 可自定义角色、模型、工具和分工 | 可配置执行方式与成员，仍需满足当前阶段约束 |
| 人工参与 | 随时提问、纠正、停止，也可额外设置确认点 | 关键阶段默认设置确认点，可查看、编辑和退回成果 |
| 完成判断 | 必要检查通过；用户要求人工验收时等待确认 | 必要检查通过，并完成适用的阶段及最终人工确认 |

模式按任务选择，同一项目可同时保存两种模式的任务；项目可以设置新任务默认模式，未配置时默认自由模式。所有模式共享项目资料、扩展、记忆、协作与权限体系，自由度不扩大工具权限或首版业务范围。

### 5.3 自由模式

- 用户可自行指定目标、上下文、Skill 组合、MCP、模型和协作成员；也可以只给目标，由 Agent 提出并执行步骤。
- 不强制生成完整需求文档或经过全部开发阶段。用户可要求“先出方案等我确认”“只研究不改代码”等，形成当前任务的额外确认点或执行约束。
- 用户可以直接参与成果修改、补充材料与调整方向；有关键缺失、危险操作、预算变化或自设确认点时仍等待对应决定。
- 用户没有要求人工验收时，按既定检查条件自动判断结果并交付；用户提出异议后在原任务继续处理。

### 5.4 需求开发模式的预置流程

沿用需求澄清、规划、执行、验证修复与交付的主线，将其展开为以下可观察阶段。阶段 Skill 名称是产品预置资源标识，本文不表示已经创建或实现这些资源。

| 阶段 | 预置阶段 Skill | 主要输入 | 必须形成的成果 | 默认人工参与 |
| --- | --- | --- | --- | --- |
| 1. 需求澄清 | requirement-discovery | 用户目标、材料、已有项目 | 需求说明、范围与不做项、验收条件、待决问题 | 确认本轮需求基线；关键问题未解决不进入后续实作 |
| 2. 方案设计 | solution-design | 已确认需求、现有项目约束 | 方案、改动范围、主要交互或接口影响、风险与验证方法 | 确认方案及关键取舍后进入开发准备 |
| 3. 任务拆解 | task-breakdown | 已确认需求与方案 | 任务列表、依赖、分工及逐项完成条件 | 默认自动推进，用户可调整；超出已确认范围时返回确认 |
| 4. 开发实现 | implement-change | 任务与分工、授权范围 | 代码、文件变更、运行方式与执行记录 | 已授权范围内自动执行，可随时纠正、停止 |
| 5. 测试与修复 | verify-and-repair | 当前变更、验收条件 | 检查记录、失败项、修复结果和必要回归证据 | 默认有限自动修复；阻塞或预算变化请求用户决定 |
| 6. 验收评审 | acceptance-review | 需求基线、成果、检查证据与预览 | 条件覆盖清单、剩余限制、待验收版本 | 用户确认验收，或说明问题并退回对应阶段 |
| 7. 成果交付 | deliver-result | 已验收成果与确认记录 | 文件和代码包、运行说明、变更与检查摘要 | 默认自动整理交付，交付校验失败仍须修复或说明 |

阶段可以复用已有需求、方案或测试证据，但必须说明对应版本、适用范围与复用理由，不能因为用户上传了一个文档就自动视为已经确认全部阶段。用户已经明确批准的同版本成果可直接记录其授权来源，避免重复确认。

### 5.5 阶段方法与推进规则

- 每个阶段 Skill 定义适用目标、所需输入、行为指引、所需能力、产出格式、退出条件以及是否存在人工确认点。
- 阶段状态由实际成果、检查结果和确认记录共同决定，不能仅凭 Agent 声称“已调用 Skill”就推进。
- 任务记录流程模板版本、阶段 Skill 版本和实际成果。更新预置流程或 Skill 不静默改变进行中的任务，显式重载时展示影响。
- 用户可扩充阶段方法或使用自定义 Skill 替代默认方法，但需保留必要输入、输出、检查和人工确认约定；替代不等于删除验收条件。
- 实现和测试可由多个协作者并行完成，主 Agent 负责收敛本阶段成果；个别成员结束不代表当前阶段已经通过。
- 阶段方法按当前执行器支持的方式加载，记录实际版本和装配结果；缺少必要能力时说明阻塞。执行器原生轮次结束不等于平台阶段或整项需求已通过。
- 前置阶段未完成、必要检查失败或确认待处理时，不进入依赖其结果的下一阶段。允许不产生实作副作用的准备工作，但不得冒充已通过流程。
- 模板标记为可选的步骤可以在说明理由后跳过；必要阶段的成果和确认要求不能由模型自行删除。默认流程的七个阶段都有对应成果要求。

### 5.6 人工参与与变更闭环

- 人工确认卡展示阶段目标、当前成果、变更摘要、未决问题及下一步影响；提供通过、补充要求、修改成果、退回等操作。
- 默认在需求基线、方案和最终验收设置人工确认点，日常开发、常规测试与有限修复自动推进。自由模式也可由用户加设相同确认点。
- 通过只对展示的成果、需求和版本有效，未响应不视为同意。刷新、断线或重启后，已经保存的确认结果与待处理卡片仍可恢复。
- 用户修改需求、方案或成果后，检查哪些已通过阶段受影响；受影响确认失效并重新评审，未受影响成果保留，不要求无差别全部重做。
- 用户退回时记录理由和目标阶段。Agent 按反馈调整后重新提交，不能用继续调用工具来绕过拒绝。
- 用户可以明确预先批准具体范围内的阶段推进，系统记录其范围与版本；不得从含糊的“继续”推断永久跳过所有确认点。
- 阶段确认与工具授权相互独立：批准方案不等于允许破坏性操作，批准一次工具调用也不代表阶段验收通过。

### 5.7 模式切换

- 新任务可以自由选模式；运行中切换先停止或等待安全点，展示已有成果和受影响流程，再由用户确认切换。
- 从自由模式进入需求开发模式时整理现有材料、识别已具备成果和缺失阶段；不得补造历史批准或检查结果。
- 从需求开发模式进入自由模式时保留阶段历史及未完成项，解释后续不再按原流程自动推进；切换本身不把原需求标记为已验收。
- 当前任务目标、成果版本、预算、权限、记忆和成员关系不因切换而静默清空或扩大。进行中的成员停止或重新获得自洽指派后才继续。

## 6. 项目与材料

### P-01 创建与导入

- 空项目可直接开始任务，不强迫用户先命名或配置技术栈。
- 上传显示进度、成功文件和失败原因，失败文件可重试。
- ZIP 导入展示目标目录，拒绝越出项目目录的路径及不支持的特殊文件。
- 公开仓库导入可指定分支或提交；导入后显示来源及导入版本。首版不连接私有账户。
- 同名文件默认保留旧文件并提示选择替换或另存，导入不会静默清空项目。
- 导入内容是任务材料，不具有提升工具权限的效力。

### P-02 文件与资料

- 文件树区分输入材料、工作文件和交付成果；同一文件可同时是工作文件和交付成果。
- 首版内联查看文本/代码、Markdown、CSV、常见图片和受支持的 HTML；其他文件可下载，不宣称一定能解析或编辑。
- Agent 无法读取某种材料时说明限制并请求可用格式，不按文件名猜测内容。
- 文件内容可能含指令，但不能改变用户目标、项目访问范围或授权。
- 用户通过任务指令修改文件；首版文件面板以查看、下载和变更检查为主。
- 可查看和下载已有交付版本。恢复历史版本覆盖当前项目文件前，须停止受影响执行、展示变更范围并确认；无法还原的运行状态和已发生网络操作明确说明，不能承诺全部撤销。

### P-03 长期保留与计算生命周期

- 关闭网页不停止后台任务；再次打开从最新状态和历史继续。
- 没有运行任务和活动预览时，计算环境可自动休眠；持久项目文件不因此删除。
- 等待用户答复或授权时可回收闲置计算，等待状态和问题保留。
- 唤醒后恢复项目资料和可恢复的任务上下文，不承诺任意进程内存原样恢复。
- 项目资料默认保留至用户删除；存储不足时限制新增并提示处理，不静默淘汰旧成果。

## 7. 任务调度与执行中干预

### T-01 并发默认

- 同一项目同一时间只执行一个任务，其余进入可见队列；不同项目可在账户额度内并行。
- 排队任务可调整顺序、取消或修改尚未执行的要求。
- 运行任务等待关键问题或授权时，项目队列暂停，避免后续任务先修改其依据。用户可停止当前执行，让其他任务继续。
- 子 Agent 是当前任务内部的工作分派，不独立绕开项目队列或扩大权限。
- 持久协作成员可在当前任务内并行处理独立工作，但只能在各自修改区写入；对项目共享文件的应用由主 Agent 检查版本并串行协调。项目级单任务执行限制不等于每项任务只能有一个 Agent。
- 项目级串行是共享资料的产品默认，不承诺底层只能串行。

### T-02 普通补充与立即纠正

- 空闲时发送消息，启动新的执行轮次。
- 执行中普通发送进入待执行队列，显示排队状态，可编辑或撤回未投递消息。
- 仅在要求已保存后承诺刷新可恢复；保存失败时显示未保存并允许重试，不创建重复输入。已经进入投递边界的消息不能误报编辑或取消成功。
- “立即纠正”明确尝试将补充送入当前执行，分别显示正在投递、已接收或无法插入。
- 无法插入时，不自动显示已生效，也不自动丢弃；用户选择排队，或停止当前执行后处理。
- 一条消息不能既被当前执行处理，又在下一轮无提示地重复处理。
- 用户发出新的约束后，界面显示接收情况；已经完成的操作不会因一条纠正消息被描述成从未发生。

### T-03 停止与继续

- 停止终止当前执行及其内部子任务，不删除任务、文件或对话。
- 停止处理期间显示“正在停止”，确认后才显示已停止；在途操作的结果不明时提示待核对。
- 停止后保留已保存的部分成果和最新检查结果，用户可继续原目标或修改要求再继续。
- “继续”从最近可恢复进度重新判断剩余工作，不等于复原任意进程或重放所有操作。
- 执行结束后，未发送的补充仍有明确状态；停止时默认暂停本任务的后续消息，用户选择继续或移除，避免停止后立刻自动重新开工。

### T-04 归档与删除

- 归档用于收纳任务，不删除成果和历史；运行中的任务须先停止或等待结束。
- 归档整个项目时同样要求没有运行执行；恢复归档只恢复可见性，不自动消费旧消息或启动计算。
- 删除任务前展示影响范围，不能无提示删除被其他任务使用的项目文件。
- 已发布的任务成果版本随任务删除移入回收区，项目当前文件独立保留，除非用户同时选择删除。
- 删除项目前必须停止相关执行并确认影响范围，项目资料及其任务一并移入回收区。

## 8. 澄清、权限与预算

### A-01 澄清原则

- 澄清问题只有影响目标、输入可用性、成果形式或关键约束时才阻塞执行；需求开发模式的阶段确认及用户自行设置的确认点按对应流程独立处理。
- 一次集中提出当前已知的关键问题，每项提供可接受的建议。
- 用户可回答、修改目标或停止；未答复不视为同意。
- Agent 不能通过给自己增加前提，把用户要求改写成更容易完成的任务。

### A-02 默认权限

- 当前任务内的项目文件读取、常规创建与修改、正常构建测试以及获准的公开网络读取默认允许。
- 批量删除、破坏性重置、可能丢弃未交付变更的回退、显著扩大授权范围或增加预算，需要确认。
- 访问其他项目、平台内部文件和凭据属于禁止范围，不通过一个通用确认框放行。
- 用户运行的代码不可获得平台模型凭据或平台账户访问权。
- 外部发送、推送、部署等首版不支持的动作，应说明限制，不引导用户点击确认来绕过范围。

### A-03 确认卡片

展示拟执行动作、目标文件或范围、原因、风险及批准后允许的具体操作。支持批准本次、拒绝、补充说明；首版不提供无限范围的永久授权。

授权只对应展示的参数与当前任务版本，参数或范围变化需要重新判断。审批被撤销、任务停止或所属账户变化后，旧授权不再使用。审批系统异常时不能默认当作已批准。

### A-04 预算

- 开始前显示本次上限，执行中显示已知用量或估算；估算与实际值区分。
- 达到时间、调用或费用上限时停止继续派发工作，交付已保存成果与未完成项。
- 扩大预算需要用户确认，不能以修复或子任务名义绕过总额。
- 暂无准确费用时明确显示估算，不展示伪精确数字；不做无依据的完成时间保证。

## 9. 计划、进度与自主协作

### E-01 计划

- 计划说明主要步骤、依赖、预期交付物与检查条件，不展示内部推理过程。
- Agent 可根据真实观察调整步骤；影响交付范围或关键假设时在时间线说明原因。
- 用户新增要求保留原要求及变更记录，重新检查受影响的计划和成果。
- 不允许为了通过检查而静默删除验收条件。
- 自由模式可动态组织计划；需求开发模式将计划绑定当前流程阶段，重规划不能绕过尚未通过的前置条件与人工确认。

### E-02 进度

- 显示当前步骤、已完成步骤、最近活动及需要用户处理的事项。
- 工具记录展示工具名、对象、简短结果、耗时与错误；大日志可展开或下载，凭据脱敏。
- 没有可靠总量时使用阶段和活动信息，不伪造百分比。
- 无进展、重试、疑似重复调用和明确达到限制分别提示，不一律显示“执行失败”。

### E-03 两种协作方式

- 默认单 Agent 工作。相互独立的小任务可使用临时子 Agent，完成后返回结果，不占用持久成员入口。
- 用户启用协作模式后，可创建具有独立会话、职责和模型配置的持久协作者。成员可以重复接收指派、被追问和继续工作，不在一次回复后消失。
- 持久协作者与临时子 Agent 分开展示，不能用其中一种的结果冒充另一种已经执行。
- 不要求每项任务都配置团队。用户开启协作、明确创建成员及数量后才建立持久成员；后续优先复用已有成员，新增超出约定范围的成员需要确认。

### E-04 创建、指派与汇报

- 协作区展示主 Agent、成员职责、实际模型、权限、运行状态及待处理事项，用户可打开每个成员的独立对话。
- 创建成员时可以附带初始任务；只创建而未指派时显示空闲，不能显示已经开始工作。失败创建不得留下不可见的后台执行。
- 用户可直接指派成员，也可让主 Agent 分解与分派。指派包含目标、关键决定、约束、输入引用和完成条件，不能假定成员看过主对话。
- 成员以可识别身份向主 Agent 报告结果、阻塞或问题，主 Agent 汇总并完成最终交付。直接对成员讲话时，相关决定与结果须在主任务留下可见记录。
- 普通成员消息按队列投递，立即调整显式选择；返回实际投递、排队或插入结果。收到消息不等于已经开工，开工不等于已经完成。
- 后台结果到达时主动更新协作区和主任务，不要求用户手动轮询成员。

### E-05 权限、模型和文件

- 每个成员有独立权限配置，不能因主 Agent 权限较高就自动获得相同权限；最终能力受项目范围、成员授权和当前任务约束共同限制。
- 成员可以选择不同模型；创建与指派前显示实际使用配置，不把默认配置当作已经切换成功。
- 同一协作任务的成员共用总预算，并分别记录消耗。成员与临时子 Agent 都不能绕过项目访问范围。
- 共用项目资料不意味着可以同时覆盖同一文件。成员默认读取共同输入，在独立修改区生成文件或代码变更；主 Agent 检查基线与冲突后应用到项目。
- 出现冲突时保留各自结果并显示差异，不以最后完成者静默覆盖。可在项目工作空间内保存代码版本，但应用成果不等于向外部仓库提交。
- 成员可读取当前项目允许的记忆；不同成员并发更新同条记忆时须检测冲突，不能静默丢失记录。

### E-06 停止、恢复与归档

- 支持停止单个成员与停止整个任务；后者覆盖主 Agent、所有成员和临时子 Agent，并保留、暂停未执行指派。
- 成员等待信息或授权时，其他不依赖该条件的成员可以继续工作；主 Agent 不能越过缺失条件宣称任务已完成。
- 页面关闭不解散协作组。恢复后保留成员身份、对话、指派和实际状态，不因为重新连接重复派发。
- 成员完成后仍可追问和再次指派。归档保留历史，恢复归档不自动消费旧消息；解散前停止运行成员，不能留下不可见的执行。
- 子任务或成员失败不立即代表整个任务失败，主 Agent 根据必要条件决定调整、重新指派或交付部分结果。

## 10. 成果、验收与修复

### D-01 成果卡片

包含名称、类型、所属任务、版本、生成时间和适用操作。文件必须真实存在并通过访问检查后才能显示下载入口；文本中提到路径不代表已交付。

成果区域区分最终交付、部分成果和临时工作文件。后续修改生成新交付版本；旧交付版本可识别，不被当前文件覆盖后仍冒充原版本。

### D-02 完成判断

- 对照本轮用户要求列出必要条件与建议条件，明确检查方式。
- 文件存在性、格式、程序运行与关键计算优先使用可执行检查。
- 报告关键事实关联来源，来源缺失、冲突或无法核实时明确说明。
- 语义审查辅助判断，不覆盖确定性检查失败；没有运行的检查显示“未核实”。
- 自由模式的必要条件全部通过且用户设置的确认点已完成，才能显示已完成；需求开发模式还须完成适用阶段、最终人工验收及交付校验。必要检查通过但尚待阶段确认时显示等待确认，不误标为部分失败或已完成。
- 存在未满足或未知的必要条件时，显示仍在修复、部分完成或无法完成及具体原因；不得用跳过流程或切换模式掩盖未完成条件。
- “执行结束”“模型回复结束”“成果已生成”和“验收通过”不能相互替代。

### D-03 修复

- 检查失败时在预算内定向修复，再执行相关检查和必要回归检查。
- 达到修复次数或预算上限时保留结果，说明失败项、已尝试措施和可选下一步。
- 用户可选择补充材料、调整目标或增加预算继续，不要求重新创建全部项目。
- 最终摘要包含成果入口、主要变更、检查结果和限制；不能只回复“完成了”。
- 需求开发模式中，用户验收未通过时按问题退回需求、方案、实现或测试阶段，保留未受影响的成果与已有反馈。

## 11. 预览与下载

### V-01 两类预览

静态内容预览用于报告、图表和 HTML 等已保存成果；运行预览用于工作空间内启动的应用。运行预览需要相关进程和计算在线，不代表公开部署或长期托管。

### V-02 生命周期与访问

- 运行预览显示启动中、可访问、已停止或启动失败；启动失败提供摘要及日志入口。
- 默认只有所属用户可访问，不提供公开分享入口。
- 预览页面与平台账户环境分开，不能取得平台登录信息或跨项目访问。
- 工作空间休眠后，运行预览显示需唤醒；静态成果仍可查看或下载。
- 删除、撤销授权或账户切换后，旧入口不可继续取得受限内容。
- 用户刷新页面不能重复启动多份同一预览服务。

## 12. 工具扩展、个性化、记忆与模型

### K-01 Skills

- 提供预置方法包，也支持从扩展目录安装、从文件包或公开仓库导入用户方法包，不按方法包名称限制任务范围。
- 安装时展示来源、版本、内容与所需工具。Skill 是行为指引，不因安装而获得额外权限；第三方内容按其真实审核状态标注，不能把下载校验通过显示成已通过安全审核。
- Agent 可以按任务选择，用户也可显式指定；结果记录本轮实际使用的名称和版本。
- 支持用户默认与项目启停，项目显式设置优先，并可恢复继承。区分已安装、已启用、当前执行已加载、更新待生效和不可用，并解释原因。
- 更新或禁用默认影响后续执行，不能静默替换当前执行的方法。涉及撤销权限的禁用立即阻止后续相关操作，不能等到下一轮才执行安全撤销。
- 用户目标、平台权限和预算优先于方法包内容，方法包不能自行授权。
- 自由模式允许自主组合 Skill；需求开发模式由当前阶段加载预置方法，可扩展或替代实现方式，但不能因此取消阶段产出、检查或人工确认要求。
- 方法包更新展示差异和权限变化，失败时保留原版本。支持卸载，卸载不删除由其生成的用户成果。
- 用户可以让 Agent 把已验证流程整理为方法包草稿，检查内容和权限后安装；生成草稿不自动安装、启用或公开发布。

### K-02 记忆

- 记忆以账户和项目隔离，项目内不同任务及兼容模型可复用。账户长期指令独立管理，不能因为记忆被标为用户偏好就自动传播至其他项目。
- 新项目默认关闭自主长期记忆；用户开启后，Agent 可根据持久价值自主新增和更新，无需每条再次确认。用户说“记住”属于显式保存信号；关闭状态下应提示开关与生效范围，不偷偷开启自动记忆。
- 支持偏好、反馈、项目、参考四类记录。反馈包含原因和适用方式，项目决定记录缘由；不把临时进度、源码结构、可重新读取的工具原文或已经写入项目规则的内容重复保存。
- 每条记忆有简短摘要、内容、类别、项目、来源任务及更新时间。更新前先查已有记录，优先修订相关项，避免重复；并发写入冲突时重新读取后处理。
- 启动时按预算提供索引摘要，详情按需读取和检索，不把所有历史对话和记忆正文全部塞进上下文。
- 用户可搜索、查看、编辑、删除单条、清空项目记忆，并能看到本轮新增或变更；自主保存不等于不可见地积累用户档案。凭据不进入记忆。
- 整理或审查先提供建议，合并、删改须有明确操作和变更记录；审查模型失败不删除或覆盖已有记忆。日常自动写入不因此变成每条审批。
- 关闭后停止后续自动读写和新执行的记忆注入，仍可查看或清理旧记录。运行中已加载的上下文无法凭空擦除，界面解释生效范围，用户可停止后重新加载。
- 删除或修改影响后续使用，不静默改写历史对话和已交付成果。记忆管理不等于删除对话，需要排除历史影响时可新建不继承旧对话的任务。
- 任务进度和恢复依赖任务记录，不能用记忆代替检查点；压缩对话不等于已经保存了全部长期信息。

### K-03 模型

- 用户先选择可用执行器，再在其支持的模型与供应商范围内选择；未选择时使用该执行器的默认配置，不假定任意引擎和模型可以自由搭配。
- 本轮记录实际模型，执行中切换默认作用于下一轮；不能把配置已改显示成当前调用已换模型。
- 模型或环境不支持某能力时解释原因，避免显示可点击但无效的入口。
- 首版只承诺受控平台执行方式，不要求用户导入本地客户端订阅或安装模型。
- 协作成员可以独立选模型，主 Agent 改变配置不静默替换所有成员的模型。
- 模型目录与真实认证访问能力分开，无法访问或不支持时明确说明；切换执行器依照 K-08 的会话交接规则。

### K-04 扩展中心与连接配置

- 扩展中心统一发现与管理插件、MCP 连接和 Skill，详情明确类型，不能把三者混称为同一个对象。首版支持可用扩展目录和用户导入，不包含公开发布、交易与评分市场。
- 插件可以打包工具、方法和资源；安装详情显示作者或来源、版本、校验结果、审核状态、声明权限、运行位置和兼容性。校验哈希用于检查完整性，不等同于作者可信或内容安全。
- 支持自定义远程 MCP 地址，以及云端兼容的 MCP 服务启动配置。连接需通过配置校验和连通性测试后启用，不能直接在平台宿主执行任意命令。
- 连接器可以配置所需凭据，展示未配置、已连接、失效和撤销状态，支持重连与删除。平台只将凭据交给获准的连接和调用范围，不写入项目文件、普通命令环境、日志或模型上下文；需要发送给第三方服务的事实应明确告知。
- 平台基础能力由系统管理；可选扩展支持用户默认与项目覆盖，显示最终启用状态及其来源。未知或未完成注册的工具不能仅凭名称得到权限。
- 插件工具和捆绑方法的作用域分别可见。停用插件时，其专属工具与未独立启用的方法一并停止后续使用，不能留下用户看不见的全局行为影响。
- 安装、项目启用、连接就绪和当前任务已加载是不同状态，配置缺失时提示具体原因，不用“已安装”暗示已经可调用。
- 扩展安装不等于授权所有业务动作。首版仍禁止第三方网站登录代操作、对外发送、推送和部署；即使扩展声明了这些工具，也不得通过安装绕过产品范围。

### K-05 扩展生命周期与云端适配

- 安装先验证包结构、兼容性和资源限制，再提交可用版本。路径越界、损坏或超限时失败，不覆盖已有资料。
- 更新展示版本、工具和权限差异，新增权限须确认；未批准或更新失败时保持原版本。卸载撤销后续调用和连接注册，保留用户产物，说明相关凭据是否同时移除。
- 当前执行使用已加载版本快照；更新后提示后续新执行或显式重载生效。紧急停用、撤销凭据和收紧权限立即阻止后续相关调用，在途动作则说明是否已生效或仍待核对。
- 插件运行在用户所属的云端隔离环境，不能因插件本身采用某种进程协议就宣称已经具备安全隔离。需要桌面窗口、用户本机文件或操作系统能力时显示不兼容，不静默扩大云端权限。
- 安装、更新、卸载中断后有明确恢复结果，不让界面显示已安装而实际不可用，也不让旧扩展在失去授权后继续后台运行。

### K-06 长期指令与项目约定

- 个性化页面提供账户级长期指令，例如语言、表达方式、常用技术偏好；项目设置提供项目约定。两者是用户主动编辑的规则，区别于 Agent 自主整理的记忆。
- 账户长期指令保存于云端账户，项目约定只用于所属项目；保存成功与失败必须明确反馈。首版每份文本最多 8,000 字符。
- 平台权限与安全限制优先；在允许范围内，当前任务明确要求优先于项目约定，项目约定优先于账户偏好。记忆提供参考，不覆盖当前明确要求。
- 修改默认对新任务生效；已有任务可以在停止当前执行后显式重载配置并开始新执行。界面显示已加载版本，不能把设置已保存显示成所有运行成员已经更新。
- 用户可预览实际生效的规则来源，清空或恢复默认。敏感凭据不应写入长期指令；指令会随任务发送给所用模型，页面说明此用途。

### K-07 个性化运行设置

- 可设置默认任务模型、临时子 Agent 的默认模型，以及命名、记忆审查等辅助工作使用的模型和回退选项；不支持的配置明确解释。
- 协作成员的职责、模型与权限分别配置，不能用一个账户默认替代实际成员配置。
- 支持选择平台或引擎提供的上下文整理策略，显示适用范围；引擎不允许调整时解释限制。整理对话与写入长期记忆是不同动作，不承诺达到阈值就已保存全部信息。
- 全局默认的修改影响后续新任务；任务和成员的显式配置保留，不在后台悄悄被全局设置覆盖。

### K-08 执行器、原生会话与能力

- 首批接入 Claude Code 和 Codex，平台展示实际执行器、认证就绪与支持能力。认证未就绪时提示处理，不能因为用户本地曾经登录就宣称云端已连接。
- 原生工具与平台扩展工具分别标识，工具活动、交互及终态来自真实执行渠道，不能用界面演示或一条进程成功消息冒充完整执行。
- 同一执行器支持继续时使用对应原生会话；跨执行器默认建立新会话并显式交接目标、约束、项目文件与必要摘要，不承诺原生历史和内部状态无损迁移。
- 即时纠正、会话恢复、工具审批、Skills 装配、子 Agent 和上下文设置按执行器实际能力提供；不可用时解释原因，不能静默假装成功。
- 原生工具同样受平台权限与业务范围约束。无法可靠实施的能力保持不可用，不能仅靠提示词要求执行器遵守。
- 平台记忆、长期指令与执行器配置分别管理，避免隐含的原生记忆或用户目录越过项目与账户边界；不能将底层自动整理或保存会话显示成平台已经保存全部长期信息。
- 持久协作者可以使用不同执行器，身份、职责与预算仍由平台管理。临时子 Agent 由对应执行器能力承载，结果标明实际执行渠道。

## 13. 异常与恢复

| 情况 | 用户看到什么 | 系统默认行为 |
| --- | --- | --- |
| 页面断开 | 重新连接提示 | 后台继续，重连补齐状态；不重复提交消息 |
| 工具临时失败 | 重试中及简短原因 | 有限重试，持续失败后调整方案或说明阻塞 |
| 等待信息/授权 | 待处理卡片 | 不把超时视为同意，不继续依赖该条件的工作 |
| 工作进程异常 | 恢复中或需手动继续 | 恢复最近已保存进度，不宣称原进程完整复活 |
| 操作结果不明 | 待核对 | 核对后再决定重试；无法核对的危险操作不重复执行 |
| 文件或空间不足 | 明确容量提示 | 停止新增写入，保留已有文件和恢复入口 |
| 源材料不可访问 | 说明受影响的结论或步骤 | 请求替代材料，不能编造来源 |
| 无进展或达到预算 | 已停止及剩余工作 | 保存部分成果，允许调整目标或确认后继续 |
| 预览进程退出 | 预览已停止或失败 | 文件保留，可重新启动；不把整个任务直接标为失败 |

自动恢复必须保留原目标、约束、授权与版本关系。恢复无法保证安全时转为人工继续；不能为了看起来连续而无提示重做有副作用的动作。

## 14. 页面结构

### 14.1 项目列表

新建、导入、搜索项目，展示最近活动、运行/等待提示和存储使用。支持归档和删除入口，危险动作有范围说明。

### 14.2 项目工作台

- 左侧：项目切换、任务列表、排队顺序和文件导航。
- 中间：当前任务对话、计划、关键活动、澄清/授权卡片、成果摘要。
- 右侧：文件、代码变更、静态或运行预览、检查结果；按用户选择切换。
- 底部输入区：目标输入、附件、模型/Skill、普通发送与立即纠正；执行中提供停止。
- 顶部：项目与任务名称、任务模式、执行器及模型、当前状态、预算和运行环境提示；新任务入口显示模式用途与项目默认值。
- 需求开发任务展示阶段导航、阶段成果、检查与确认记录，当前阶段高亮，未通过阶段说明阻塞原因；自由任务以目标、动态计划和成果为主，不强制展示完整开发流程。

窄屏允许收起侧栏，但首版以桌面浏览器为主要使用形态。技术日志不阻塞用户查看目标、待处理事项和成果。

### 14.3 设置

账户长期指令、项目约定、默认及辅助模型、预算、记忆管理、扩展中心与连接状态、项目容量和删除管理。不展示尚未实现的多设备连接入口。

### 14.4 扩展中心与协作区

扩展中心按插件、连接、方法分别展示可安装目录与已安装项，提供来源、权限、配置、项目启停、更新与卸载入口。项目工作台可查看本次任务实际加载的能力及配置来源。

任务协作区展示主 Agent 与持久成员，可打开独立会话、创建或归档成员、指派、排队补充、立即调整和停止。临时子 Agent 以执行细节展示，不混入持久成员列表。结果与阻塞按实际成员汇总，不能只显示主 Agent 已回复。

## 15. 状态语义

任务长期存在，归档/回收是管理属性；每次执行独立记录状态。任务列表展示最近执行状态及是否有待执行消息。

| 执行状态 | 含义 | 常用动作 |
| --- | --- | --- |
| 待执行/排队 | 已收到目标但尚未开始 | 修改、撤回、调整队列 |
| 执行中 | 正在规划、操作或检查 | 查看、补充、立即纠正、停止 |
| 等待信息 | 缺少必要用户输入 | 回答、修改目标、停止 |
| 等待授权 | 特定操作尚未获准 | 批准本次、拒绝、说明、停止 |
| 等待阶段确认 | 阶段成果已提交，等待用户决定 | 查看、通过、编辑、补充、退回、停止 |
| 正在停止 | 已请求停止，仍待确认 | 等待、查看在途操作 |
| 已停止 | 当前执行已结束，目标未必完成 | 查看部分结果、继续 |
| 恢复中 | 正在恢复已保存进度 | 查看进度、停止 |
| 已完成 | 必要条件通过 | 查看成果、下载、继续修改 |
| 部分完成 | 有可用结果但必要条件仍缺失 | 查看差异、补充、继续 |
| 无法完成 | 当前条件下无法完成目标 | 查看原因、调整目标、重试 |

“待执行消息”“运行预览”和“归档”各自展示，不塞进一个互相覆盖的状态标签。

需求开发模式另行记录每个阶段的待开始、进行中、待确认、需修改、已通过状态。流程阶段、执行活动和任务归档是不同维度；用户通过阶段后可以开始下一轮执行，不能把一次模型回复结束当作阶段已通过。

## 17. 发布验收场景

| 编号 | 场景 | 必须观察到的行为 |
| --- | --- | --- |
| AC-01 | 自由模式空项目提交明确目标 | 展示计划并执行，不额外要求确认计划；用户另设确认点时遵守约定 |
| AC-02 | 关键条件缺失 | 集中提问，未回复不假定用户同意 |
| AC-03 | 研究任务交付报告 | 真实文件可打开，关键事实可定位来源，未知项被标注 |
| AC-04 | 上传 CSV 并生成图表 | 输出数据、图表及口径说明，计算结果可复查 |
| AC-05 | 生成应用并预览 | 可访问受控预览，区分运行服务和已保存代码 |
| AC-06 | 同项目启动第二任务 | 显示排队，不与前任务同时修改项目 |
| AC-07 | 执行中普通补充 | 可见队列、可编辑撤回，不误显示已经生效 |
| AC-08 | 立即纠正不可用 | 明确失败或不支持，用户可选排队或停止后执行 |
| AC-09 | 用户停止后继续 | 当前执行真正停止，资料保留，补充消息不立即自动重启 |
| AC-10 | 页面断开重连 | 后台进度保留，状态补齐，无重复任务；已保存的待答复/授权卡仍可处理 |
| AC-11 | 进程异常或结果不明 | 明确恢复情况，不盲目重复危险操作 |
| AC-12 | 破坏性操作待批准 | 展示范围，拒绝后不能执行，参数变化不能复用旧批准 |
| AC-13 | Agent 说完成但文件不存在 | 不提供假下载入口，必要交付检查不通过 |
| AC-14 | 检查失败并耗尽修复预算 | 显示部分完成或无法完成，保留结果和失败项 |
| AC-15 | 用户修改目标 | 保留变更记录，重新检查受影响条件，不沿用旧成功结论 |
| AC-16 | 更新 Skill 或切换模型 | 当前实际版本不被静默改写，说明新执行或显式重载的生效方式 |
| AC-17 | 关闭或删除记忆 | 后续自动读取和注入停止，已加载的运行上下文与历史对话有清楚说明 |
| AC-18 | 跨账户读取项目或预览 | 拒绝访问；切换账户不能复用旧权限和记忆 |
| AC-19 | 计算休眠 | 成果文件保留；运行预览提示唤醒或重启 |
| AC-20 | 删除/恢复项目 | 停止相关执行、撤销访问，回收区内可恢复，永久删除需确认 |
| AC-21 | 达到容量或预算 | 明确限制并保留已有成果，不静默删除或突破额度 |
| AC-22 | ZIP 越界或项目材料含恶意指令 | 拒绝越界，不因材料文本扩大权限 |
| AC-23 | 恢复历史成果覆盖当前文件 | 执行中拒绝恢复；确认范围后恢复，不冒充回滚全部运行副作用 |
| AC-24 | 安装扩展并在项目启停 | 类型、来源、审核与权限可见；项目覆盖可解释；不会有不可见的捆绑方法继续生效 |
| AC-25 | 配置 MCP 及凭据失效 | 配置和连接就绪分开；失效时明确提示，不向日志、项目文件或普通命令暴露密钥 |
| AC-26 | 更新损坏或新增权限 | 校验失败或未获授权时旧版本保持可用；不静默提升权限 |
| AC-27 | 运行中紧急停用扩展 | 后续相关调用立即被阻止，版本快照和在途动作结果分别说明 |
| AC-28 | 启用自主记忆后表达稳定偏好 | 自动保存可查看的记录，无逐条确认；同项目新任务可检索与复用 |
| AC-29 | 用户偏好分类与项目隔离 | 项目 A 的偏好记忆不因分类名称而流入 B；账户长期指令按其范围独立应用 |
| AC-30 | 修改长期指令 | 保存成功明确，新任务使用新版；已有任务和协作者不被误报为全部热更新 |
| AC-31 | 记忆整理失败或提供删改建议 | 原记忆保留；建议与实际执行分开，变更可查 |
| AC-32 | 创建持久协作者并重开页面 | 独立会话、职责、模型与历史保留，可再次指派；不被临时子 Agent 结果冒充 |
| AC-33 | 仅创建成员或指派失败 | 无任务时显示空闲；派发成功有明确回执，失败不显示正在执行 |
| AC-34 | 高权限主 Agent 指派成员 | 成员按独立配置和项目范围判权，不隐式继承更高权限 |
| AC-35 | 成员并行修改同一基线 | 各自结果保留，应用到项目时检查冲突，不按完成顺序静默覆盖 |
| AC-36 | 停止整个协作任务后恢复 | 所有执行渠道停止并确认，指派保留且暂停；恢复不重复派发或自动消费旧消息 |
| AC-37 | 扩展包含首版不支持的业务工具 | 安装不能绕过范围执行外部发送、推送、部署或第三方网站代操作 |
| AC-38 | 同项目创建两种模式的任务 | 模式按任务独立记录，项目资料可共用；项目默认不强制改写已有任务 |
| AC-39 | 需求开发模式推进阶段 | 每阶段有对应 Skill、输入输出与实际版本；仅声称调用成功不能视为阶段通过 |
| AC-40 | 阶段待确认或被退回 | 不进入依赖该结果的实作阶段；通过与拒绝均有记录，不重复索取同版本已明确授权 |
| AC-41 | 自由模式自定义工作方式 | 可组合方法、工具、模型和协作，无需补齐开发全流程；自设人工确认点有效 |
| AC-42 | 已批准后修改需求或方案 | 受影响确认失效，重新评审；未受影响成果可复用，不静默删除原条件 |
| AC-43 | 执行中切换模式 | 先处理在途执行并确认影响，保留历史，不伪造旧审批、不自动扩大权限 |
| AC-44 | 检查通过但人工验收未完成 | 显示等待阶段确认，不能标记需求已完成；批准后仍需交付校验 |
| AC-45 | 用户在验收时提出修改 | 记录问题并退回相关阶段，修复后提交新版本，保留旧成果与验收历史 |
| AC-46 | 选择执行器但认证未就绪 | 执行器、模型与认证状态分别显示，不冒充已连接或可运行 |
| AC-47 | 两种执行器分别执行和继续任务 | 各自通过真实原生会话完成输入、工具产物、交互与终态，平台保留正确身份映射 |
| AC-48 | 跨执行器继续已有目标 | 明确建立新会话及交接范围，历史可追查，不复用不兼容原生标识或宣称无损迁移 |
| AC-49 | 原生工具触发限制或审批 | 原生工具与 MCP 都受实际约束，拒绝和撤权可验证；轮次结束不能绕过阶段确认 |

## 18. 产品指标与评审

主要指标为必要条件通过的任务比例、有效交付比例、用户继续修改成功率、人工介入次数、异常恢复成功率、任务耗时和成功交付成本。统计同时包含失败执行的消耗，并按模式及研究、数据、代码任务分组。需求开发模式另观察阶段一次通过率、退回原因和人工等待时长；预设人工确认不能误计为 Agent 执行失败，不能单纯以减少人工介入评价该模式。

事件覆盖：创建/导入项目、提交任务、执行开始、进入等待、授权结果、补充排队、纠正结果、停止确认、验收结果、成果打开/下载、继续执行、预览启动/停止、环境休眠/唤醒及删除恢复；还包括扩展安装/更新/撤销、长期指令版本加载、记忆新增/修订/删除、协作成员创建/指派/汇报/停止，以及模式选择/切换、阶段开始/提交、确认/退回和确认失效。事件不收集凭据或默认上报完整用户文件及记忆正文。

上线前先完成固定样本和异常场景验收，再用质量与成本基线设定数值目标。本文不填写未经测量的成功率提升或性能承诺。

双模式及其人工参与原则、工具扩展、长期指令、自主项目记忆和持久 Agent 协作已按用户要求纳入范围。需求开发模式的七阶段划分、预置 Skill 标识、三个默认人工确认点，以及具体调度、权限与配置生效规则、数据生命周期和初始配额仍作为完整草案供整体评审。实现阶段的接口、状态存储、隔离技术、模型版本与评测实现由技术方案说明，不能用技术便利替代本文的用户行为约定。
